## 一、已修复并验证（7 项）

### 1. SEO 健康检查页 JS 语法错误 —— 整页交互瘫痪 ⚠️ 最严重

一批中文文案曾被按 GBK 误解码后存回，字节永久损坏。多数只是显示难看，但有几处**把字符串的闭合引号也吃掉了**：

```js
'AI 宸茬敓鎴? : '宸茬敤鏈湴鎽和鐢熸垚';
              ↑ 闭合引号没了，后面变成裸标识符
```

浏览器实测 `SyntaxError: Unexpected identifier`，**整个 script 块不执行**：`seoGenerateDescription` / `seoSavePage` / `seoSetMsg` 全部 `undefined`。SEO 页的「生成」「保存」按钮点了毫无反应。**德恩基生产站后台同样受影响**（同一份模板代码）。

同类损坏还吃掉过 HTML 的 `<`：`已设置?/span>`、`>新窗鍙?/option>` —— 标签不闭合。

修复：18 处用户可见文案（含 4 处引号损坏、2 处标签损坏）按语境还原。提交 `fca0f20`。

### 2. 模块变体名被污染成字符串 "None"

```
种子数据 variant: null  →  Python None
  ↓ {{ module.variant | default('default') }}
Jinja 的 default() 只处理 undefined，不处理 None  →  渲染出字符串 "None"
  ↓ 同样写法的 hidden input
点一次保存就把 'None' 回写进 YAML
```

直接跑 Jinja2 验证过：`None` 经 `default()` 得到 `'None'`，经 `or` 得到 `'default'`。

修复：两处改用 `or`（与 JS 版 `variant || 'default'` 对齐），claude 种子数据 36 处 `null` 归位成 `default`。提交 `2deaabd`。

前台**不会坏** —— `builder.py` 找不到 `variants/None.html` 会回退 `template.html`。但它污染数据、后台显示错误，且 `builder.py:2427` 的 `variant in (None, '', 'default')` 判断没包含字符串 `'None'`，被污染的模块会走不同分支。

### 3. 样式变体选了完全不生效

`applyDataPresetToModule` 对 radio 组写 `.value` 而不是 `.checked`，后果有两个：第一个选项的值被篡改（「居左」的 value 变成 `right`），且**没有任何选项被选中** —— 浏览器不提交未选中的 radio 组，样式预设整个丢失。

实测对比（同为 `hero_banner`）：

| 路径 | 落盘的 data |
|---|---|
| 换变体 | `{}` 全丢 |
| 添加模块 | `{'style_text-align': 'center'}` ✓ |

影响面已钉死：只有「换变体」路径有问题，且该功能只存在于 `panel_page_edit.html`。另外三处（`page_home.html`、`panel_detail_templates.html`、`panel_data_list.html`）只有「添加模块」分支，走 `renderDynamicFieldsGrouped` / `_buildModuleHTML` 在生成 HTML 时就带 `checked`，本来就是对的。

修复后端到端验证：radio 正确选中 → 落盘 `{'style_text-align': 'left'}` → **前台预览标题真的左对齐了**。提交 `2deaabd`。

## 二、误报及纠正（1 项）

### ❌「claude 模板手机端没有导航」是错的

初版报告把这条列为「影响生产站点的最严重问题」，**该结论是错的**，由用户的手机截图推翻并复核确认。

事实：`claude/templates/_base.html` **有**完整移动端导航 —— 272 行汉堡按钮、279 行 `mobile-nav-overlay`、310 行 `toggleMobileMenu()`。全部 10 个有构建产物的站点都带着它们。

**两个独立的错误互相印证，制造了「交叉验证通过」的假象**：

```
探测代码把汉堡按钮过滤掉了   →  「预览里 header 只有 logo」

          两条独立证据指向同一个错误结论
```

- 探测代码里写了 `if (el.children.length > 2) return;`，而汉堡按钮正是 `<button>` 里三个 `<span>`，被自己筛掉了
- Grep 返回带 `[Showing results with pagination = limit: N]`，claude 的匹配落在被截掉的部分

已从文档、memory、git 三处清除。纠正提交 `04f916e`。

## 八、踩过的坑

1. **Grep 结果被截断却当成完整结果 —— 本次最贵的教训**。返回里带 `[Showing results with pagination = limit: N]` 就说明还有没显示的匹配，此时「列表里没有 X」**不等于**「X 不存在」。本次犯了两次，其中一次导致把错误结论写进文档、memory 和 git 提交信息。**规矩：凡要下「某文件没有 X」这类否定结论，必须对该文件单独 Grep 复查。**
2. **自己写的探测代码误伤了目标**。用 `el.children.length > 2` 过滤「容器元素」，把恰好有 3 个子 `<span>` 的汉堡按钮筛没了。检测手段本身也要验证。
3. **PowerShell here-string 里的 `$`**。`\$` 不是转义（反引号才是），Python 收到的是字面 `\$`，正则会去匹配真的 `$` 字符。连续两次「替换 0 处」都源于此。**复杂正则一律写成脚本文件执行，不用 `python -c` 拼。**
4. **从终端输出复制字符串做匹配会失败**。终端渲染会把 `U+FFFD` 之类变形，复制回来跟磁盘字节对不上。改按行号定位。
5. **YAML 里 `variant: None` 不是 null**。`None` 不是 YAML 的 null 关键字（只有 `null` / `~` / 空 才是），所以它是**字符串**，但肉眼看文件极易误判成空值。
6. **CRLF 与正则**。种子数据是纯 CRLF，用 `newline=''` 保换行符时行尾的 `\r` 会挡住 `[ \t]*$`；用零宽前瞻 `(?=\r?$)` 既匹配得上又不消费 `\r`。
7. **乱码扫描的字符集容易写宽**，误报了一批完全正常的中文注释（`app/core/` 下 12 处「乱码」全是假阳性）。
8. **`/_panel/home` 直接访问没样式**是正常的 —— 那是 panel 片段，设计上要嵌在 iframe 里。
9. **`flask` 不在 PATH**，CLAUDE.md 第十节的命令表得改用 `python -m flask --app run ...`。
10. **`sites/` 在 `.gitignore` 里但有 985 个文件被强制跟踪**，提交必须用 `git add -f`。Git 对命令行显式指定的 ignored 路径一律拒绝，无论是否已跟踪。
