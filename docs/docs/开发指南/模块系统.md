# 模块系统

> 本文是《开发指南》的第四章，面向后台开发者。返回总目录见 [README.md](README.md)。

---

## 概述

模块系统是店主搭页面的核心机制——从预制的模块库中选择模块、选排版变体、填内容、拖拽排序，全程不需要接触代码。模块代码由模板开发者维护，店主只存选择 + 数据，模板升级时自动获益。

本章覆盖：模块库结构、排版变体、配置面板交互、数据存储格式、Header/Footer 变体、模块共享范围。

---

### 模块库：店主从模块池中选择并排序

**模块库是事先设计好的通用模块池，店主配置页面时从模块库中选择模块，然后拖拽排序。**

模块库包含多种类型的通用模块，按用途分：

| 类别 | 示例模块 | 说明 |
| --- | --- | --- |
| 内容模块（Content） | Hero Banner（轮播大图）、关于我们、联系方式、富文本区块 | 展示形式固定，店主填内容字段 |
| 数据模块（Data） | 产品列表、案例展示、博客列表、团队介绍 | 自动从数据集拉取数据循环渲染 |
| 功能模块（Functional） | 联系表单、地图、视频嵌入、自定义 HTML | 提供特定交互功能 |
| 组合模块（Section） | 功能特色区、客户评价区、FAQ 折叠区 | 有独立视觉主题的内容组合 |
| 布局模块（Layout） | 两栏布局、三栏布局、图文混排 | 定义页面结构骨架 |

#### 模块库的数据结构

模块的字段由 `template.html` 中的 `data-name` / `data-type` 属性自动推断，**不在 meta.yaml 中重复定义**。meta.yaml 只存模块元信息（名称、分类、图标、变体列表）。

```text
# 模块库定义（site_templates/<name>/blocks/ 目录下每个模块一个文件夹）
# 例：site_templates/dengtec/blocks/hero_banner/

hero_banner/
├── meta.yaml          # 模块元信息（不含字段定义，字段从 HTML 的 data-* 推断）
│   name: "Hero Banner"
│   category: content
│   icon: hero_banner.svg
│   variants:           # 排版样式变体
│     - key: text_overlay
│       label: 文字叠加（全宽）
│       preview: variants/text_overlay.png
│     - key: split_left
│       label: 左文右图（50:50）
│       preview: variants/split_left.png
│     - key: split_right
│       label: 左图右文（50:50）
│       preview: variants/split_right.png
├── template.html              # 默认变体的纯 HTML 片段（含 data-* 属性定义字段）
├── variants/                  # 各变体的模板
│   ├── text_overlay.html
│   ├── split_left.html
│   └── split_right.html
└── preview.png                # 默认变体的后台缩略图
```

#### 模块的排版样式变体

**每个模块可以有多个排版样式变体，店主选择模块后可以切换排版。**

例：Hero Banner 模块提供三种变体：

| 变体 | 布局 | 适用场景 |
| --- | --- | --- |
| 文字叠加（全宽） | 背景图全宽 + 文字居中叠加 | 标准首页 Banner |
| 左文右图（50:50） | 左半文字 + 右半图片 | 偏内容的 Landing |
| 左图右文（50:50） | 左半图片 + 右半文字 | 偏视觉展示的 Banner |

#### 模块的显示配置：一行几个 + 共显示几个

对于网格类模块（如产品网格、图文卡片、团队展示等），店主可以控制：

| 配置项 | 说明 | 示例 |
| --- | --- | --- |
| 每行列数（columns） | 一行显示几个卡片 | 3 列 / 4 列 |
| 最大显示数（max_items） | 总共在页面上显示几条 | 首页显示 6 个产品（即使有 50 个） |
| 数据来源（dataset） | 从哪个数据集拉取 | `products` / `posts` / `cases` |

例：产品网格模块的常见组合：

| columns | max_items | 效果 |
| --- | --- | --- |
| 3 | 6 | 2 行 × 3 列，展示 6 个产品 |
| 4 | 8 | 2 行 × 4 列，展示 8 个产品 |
| 3 | 3 | 1 行 × 3 列，简洁展示 |

#### 图文的链接配置

图文模块中，每个图文条目可以配置独立的链接：

| 链接类型 | 说明 | 示例 |
| --- | --- | --- |
| 内部页面 | 链接到本站其他页面 | `/products/smart-lock` |
| 外部链接 | 链接到外部网址 | `https://rimu.me` |
| 无链接 | 纯展示，不跳转 | — |

链接还可配置 **打开方式**：当前页打开（`_self`）或新标签页打开（`_blank`）。

- 变体的**字段定义一样**（由模板 HTML 中的 `data-name` 属性定义，不依赖 meta.yaml），数据不丢失
- 变体的**渲染模板不同**（各自有 `template.html`），布局不同
- `columns` 和 `max_items` 控制网格的视觉呈现
- 每条图文可独立配置链接和打开方式
- 切换任何配置后，中间预览区即时更新

#### 模块数据存储格式（含变体）

```yaml
# sites/<id>/pages/home.yaml
title: 首页
modules:
  - type: hero_banner
    order: 1
    variant: text_overlay       # 选用的排版样式变体
    data:
      title: 德恩基电子科技
      subtitle: 提供展示道具行业的电子产品
      background_image: /assets/images/hero.jpg
  - type: image_text            # 图文模块
    order: 2
    variant: split_left         # 图左文右
    data:
      image: /assets/images/product.jpg
      title: 智能门锁 Pro
      description: 行业领先的智能门锁解决方案
      button_text: 了解更多
      button_url: /products/smart-lock
```

**关键设计：变体只影响渲染时的模板选择，不影响数据。** 店主换变体 = 同一个数据用不同的 HTML 结构呈现出来。

#### 店主配置首页的流程

```text
店主进入后台 → 左侧点击"首页" → 右侧显示当前页面已选模块：

  ┌─────────────────────────────────────────────────────┐
  │  当前页面：首页 — 已选模块（可拖拽排序）                │
  │                                                     │
  │  ≡≡ Hero Banner（轮播大图）           [⚙ 配置] [✕]  │
  │  ≡≡ 功能特色（Feature Grid）          [⚙ 配置] [✕]  │
  │  ≡≡ 产品列表（Product List）          [⚙ 配置] [✕]  │
  │  ≡≡ 客户评价（Testimonials）           [⚙ 配置] [✕]  │
  │  ≡≡ 联系我们（Contact Form）          [⚙ 配置] [✕]  │
  │                                                     │
  │  [+ 添加模块]                                       │
  └─────────────────────────────────────────────────────┘
```

店主操作：
1. 点击 **[+ 添加模块]** → 弹出模块库弹框
2. 在弹框中浏览模块、预览排版变体 → 选择后确认添加
3. 在已选列表中拖拽模块调整顺序（≡ 图标可拖动）
4. 点击 **[⚙ 配置]** 编辑该模块的具体内容（填标题、上传图片等）
5. 点击 **[✕]** 从页面中移除该模块
6. 保存 → 模块列表和配置写入 `sites/<id>/pages/home.yaml`

交互规则：
- 左侧模块列表**纵向排列**，点击某个模块后该模块高亮（▶ 指示器），右侧切换为该模块的排版预览
- 右侧排版预览使用**浏览器实际渲染效果**（iframe 嵌入该模块各变体的真实 HTML），不是静态缩略图

- 点击 **[确认添加到页面]** → 该模块以选中的排版变体添加到页面已选模块列表末尾
- MVP 阶段每个模块提供 1-2 种排版变体，后续模板开发者可按需扩展
- 完整的可用模块清单及每个模块的 HTML 写法见 **[Block 示例库.md](../Block%20示例库.md)**

#### Header 菜单：多级子菜单（无层级限制）

**菜单支持不固定层级的子菜单。** 店主可以按需创建任意深度的菜单树，每个非首页菜单项都可以添加子菜单。

```text
头部菜单示例（多级嵌套）：
  ├── 首页 (index)                                    # 固定，不可删
  ├── 产品 (products)                                  # 一级菜单
  │   ├── 智能门锁 (products?cat=lock)                 # 二级
  │   ├── 传感器模组 (products?cat=sensor)             # 二级
  │   └── 配件 (products?cat=accessory)                # 二级
  ├── 案例 (cases)                                     # 一级菜单
  │   ├── 制造业案例 (cases?industry=manufacturing)     # 二级
  │   └── 服务业案例 (cases?industry=service)           # 二级
  │       ├── 2025 (cases?industry=service&year=2025)   # 三级
  │       └── 2026 (cases?industry=service&year=2026)   # 三级
  ├── 关于我们 (about)                                 # 一级页面
  └── 联系我们 (contact)                               # 一级页面
```

#### 子菜单下拉框的样式变体

下拉子菜单框有多种展示样式可选：

| 样式 | 布局 | 适用场景 |
| --- | --- | --- |
| **垂直列表** | 子项纵向排列（传统下拉） | 子项较少（3-5个），通用 |
| **水平平铺** | 子项横排一行显示 | 子项较多（6+个），分类清晰 |
| **网格排列** | 子项多列平铺（如3列×4行） | 大型菜单（Mega Menu），子项很多 |
| **图文卡片** | 每个子项带图标/缩略图 | 产品分类、案例分类 |

```text
垂直列表样式:                  水平平铺样式:
┌──────────────┐              ┌──────────────────────────┐
│ 智能门锁      │              │ 智能门锁 │ 传感器 │ 配件  │
│ 传感器模组    │              └──────────────────────────┘
│ 配件          │              
└──────────────┘              网格排列样式:
                              ┌──────────────────────────┐
                              │ 智能门锁 │ 传感器 │ 配件  │
                              │──────────│────────│───────│
                              │ 门禁系统 │ 报警器 │ 线材  │
                              └──────────────────────────┘
```

店主在菜单配置中为每个有子项的菜单选择下拉样式：

#### 语言切换按钮

**头部 Header 可包含语言切换按钮。** 按钮样式与下拉框的布局同样有变体可选：

| 变体 | 布局 | 适用场景 |
| --- | --- | --- |
| **水平行内** | 语言选项横排一行：`简中 ｜ 繁中 ｜ English` | 语言少（2-3种），桌面端友好 |
| **垂直下拉** | 点击按钮弹出纵向列表 | 语言较多（4+种），节省空间 |
| **旗帜 + 简称** | 下拉框内每行显示国旗 emoji + 语言名 | 国际化站，直观 |

```text
水平行内样式:                  垂直下拉样式:
┌────────────────────┐        ┌─────────┐
│ 🌐 简中 | 繁中 | EN  │        │ 🌐 语言  │  ← 点击
└────────────────────┘        └────┬────┘
                                   ▼
                              ┌──────────┐
                              │ 🇨🇳 简体中文│
                              │ 🇭🇰 繁體中文│
                              │ 🇺🇸 English │
                              └──────────┘
```

语言切换按钮在 Header 中的位置也是变体的一部分（由选取的 Header 变体决定，如：右上角固定、菜单右端、汉堡菜单内嵌）。

#### 菜单数据的存储格式

```yaml
# sites/<id>/settings.yaml
menu:
  - label: "首页"
    type: home                            # 固定，不可删
  - label: "产品"
    type: list
    target: products
    dropdown_style: vertical              # 下拉样式
    children:
      - label: "智能门锁"
        type: link
        url: /products?cat=lock
      - label: "传感器模组"
        type: link
        url: /products?cat=sensor
      - label: "配件"
        type: link
        url: /products?cat=accessory
  - label: "关于我们"
    type: page
    target: about
  - label: "联系我们"
    type: page
    target: contact
    children: []                          # 无子菜单
```

#### Header / Footer 也有模块库

头部和底部的设计变体同样是模块库中的子类，**使用与页面模块相同的弹框选择模式**（左侧列表 + 右侧浏览器渲染预览）：

| 类别 | 示例变体 |
| --- | --- |
| 顶部导航（Header） | Logo 居中 + 菜单下方、Logo 左 + 菜单右、极简风（Logo 左 + 汉堡菜单）、带顶栏（电话 + 社交图标在上） |
| 底部（Footer） | 四栏链接、三栏 + 订阅、极简单行、带地图 + 联系方式 |

店主在后台点击"网站头部"或"网站底部"配置项 → 弹出模块库弹框 → 左侧纵向列出 Header/Footer 变体 → 点击某个变体后右侧以**浏览器渲染效果**预览该变体的真实外观 → 选中后确认。

每个 Header 变体预定义了：Logo 位置、菜单排列方式、语言切换按钮位置、子菜单展开方式（点击/悬停）、移动端折叠行为。

#### 模块库的共享范围

**模块库是模板级别的，一个模板的 `blocks/` 被所有选择该模板的店主共享。**

```
site_templates/dengtec/blocks/     ← 开发者维护一份，所有选 dengtec 的店主共用
                │
    ┌───────────┴───────────┐
    ▼                       ▼
  A 店主                    B 店主
  选 dengtec                选 dengtec
  看到同一套模块库           看到同一套模块库
  各自选模块、填内容         各自选模块、填内容
    │                       │
    ▼                       ▼
sites/1/                  sites/2/
  pages/home.yaml           pages/home.yaml
  (A的模块选择+数据)          (B的模块选择+数据)
```

| 层级 | 共享范围 | 示例 |
| --- | --- | --- |
| 模板代码层（`site_templates/<name>/`） | 所有选该模板的店主共享 | `blocks/`、`templates/`、`static/css/main.css` |
| 店主数据层（`sites/<id>/`） | 每个店主独立 | `pages/*.yaml`、`data/*.yaml`、`settings.yaml` |

**不同模板的 `blocks/` 互相隔离。** 各模板的 blocks 各自独立维护，视觉风格和 HTML 结构各自不同。

#### 为什么这样设计

| 维度 | 说明 |
| --- | --- |
| **模块通用化** | 同一个 Hero Banner 模块可以出现在首页、产品页、关于页，只需在不同页面配置不同内容即可 |
| **非技术人员可操作** | 店主不需要理解 HTML / CSS，只需"选择 → 排序 → 填表"三步 |
| **模板升级友好** | 开发者改 `blocks/` 里的模块代码 → git push → 所有用该模板的店主网站自动获益，因为店主只存选择+数据，不持有模块代码 |
| **灵活性不失控** | 店主可以选择和排序，但不能修改模块代码本身。复杂度被模块边界框定 |
