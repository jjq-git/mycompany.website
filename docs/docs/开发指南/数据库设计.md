## 数据库设计

### 设计原则

数据库**只存平台级数据，不存店主网站的内容。** 这是与 WordPress 等传统 CMS 最根本的架构差异。

**关键决策：**

| # | 决策 | 理由 |
|---|------|------|
| 1 | 店主内容存 YAML 文件，不存数据库 | 导出 ZIP = 复制文件夹；平台关停时整站还能跑；换字段不用 ALTER TABLE |
| 2 | 主键用 BIGSERIAL（非 UUID） | 简单、紧凑、SQLite 友好。URL 里不暴露主键，统一用 slug 替代 |
| 3 | 删除用软删除（30 天可恢复） | 低频用户可能 6 个月才登录，误删后需要恢复窗口 |
| 4 | MVP 用 SQLite，规模化换 PostgreSQL | SQLAlchemy ORM 屏蔽差异，迁移只需改连接串 |

| 类型 | 存哪 |
| --- | --- |
| 账号、订阅、域名、发布历史 | 数据库 |
| 店主填的内容（产品、页面、设置） | `sites/<id>/*.yaml` |
| 模板代码 | `site_templates/<name>/` |

数据库文件本身与店主内容文件在目录树中的位置（完整树见 [目录结构.md](../目录结构.md)）：

```text
├── instance/                         # SQLite 数据库文件（gitignored）
│   └── app.db                        # 平台级数据：users / sites / domains / publish_versions ...
│
├── sites/                            # 店主网站内容（gitignored，每站一个文件夹，不进数据库）
│   └── <site_id>/                    # 例：sites/1/
│       ├── settings.yaml             # 站点配置（菜单树、Header 变体、启用的语言、主题变量）
│       ├── glossary.yaml             # 翻译词汇表
│       ├── pages/                    # 页面内容（店主填的数据）
│       ├── data/                     # 数据集（产品/文章/案例）
│       ├── translations/             # AI 翻译缓存：存 hash→译文 查找表，不是成品整站（成品在 output/<lang>/）
│       └── assets/                   # 上传的资源文件
```

### 表全景

```text
认证 / 用户
├── users                  店主账号
└── login_tokens           魔法链接 token

站点 / 域名
├── sites                  网站元信息
└── domains                自定义域名

模板（缓存）
└── templates              site_templates/ 元信息缓存

发布 / 自动化
├── publish_versions       每次发布的快照
└── provisioning_jobs      云资源自动化任务（建桶、绑域名、签 SSL）

订阅 / 支付
├── subscriptions          订阅计划
├── payments               支付记录
└── invoices               发票

操作日志
├── audit_log              安全 / 操作审计
└── email_log              发出的邮件

统计（缓存）
└── site_stats             从文件计算 + 缓存

i18n（Phase 2）
└── translation_jobs       AI 翻译任务记录
```

### 表详细设计

**users**

```
id                  主键（BIGSERIAL）
email               唯一，索引
email_verified_at   首次验证时间
status              active / suspended / deleted
preferred_lang      后台界面语言（zh / en）
last_login_at
created_at
updated_at
```

> 没有 password 字段 —— 用邮箱魔法链接登录。

**login_tokens**

```
id
user_id             可空（新用户首次登录时还没账号）
email               新用户登录时用，验证后创建 user
token_hash          SHA-256 哈希，不存原始 token
expires_at          默认 15 分钟
used_at             一次性使用
ip_address          安全审计
created_at
```

索引：`token_hash`、`(email, used_at)`（防刷）

**sites**

```
id                      主键
owner_id                FK → users.id
name                    店主起的名字（"我的公司官网"）
slug                    唯一短字符串（3-30 字符 [a-z0-9-]）
folder_path             站点文件夹路径（默认 sites/<id>/）
template_name           FK → templates.name
template_version        使用的模板版本
default_language        默认语言（zh / en）
enabled_languages       JSON: ["zh", "zh-Hant", "en"]  # 暂定三种，可扩展
storage_mode            shared / dedicated
bucket_name             桶名
bucket_path_prefix      路径前缀（shared 模式才用）
bucket_region           cn-hangzhou / etc.
cdn_provider            aliyun / cloudflare
status                  draft / published / suspended
last_published_at
soft_deleted_at         软删除（保留 30 天可恢复）
created_at
updated_at
```

唯一索引：`slug`（禁用保留字）、`owner_id + name`

**domains**（自定义域名）

```
id
site_id                     FK → sites.id
hostname                    "company-a.com"
status                      pending / verified / active / failed
ssl_provider                aliyun-free / cloudflare-saas / letsencrypt
ssl_cert_id                 第三方证书 ID
ssl_issued_at
ssl_expires_at              续期监控用
dns_verified_at
dns_verification_token      DNS 验证用
cdn_resource_id             云上 CDN 资源 ID
created_at
updated_at
```

唯一索引：`hostname`

**templates**（模板缓存，源在文件系统）

```
id                  主键
name                文件夹名（"dengtec"），唯一
display_name        "制造业-标准版"
industry            manufacturing / restaurant / service / trading / studio
cover_image         封面图 URL
description
current_version     当前版本
is_public           true=店主可选；false=内测
created_at
updated_at
```

> 模板真正的源是 `site_templates/<name>/meta.yaml`，这张表只是缓存。平台启动时扫描同步。

**publish_versions**

```
id
site_id                 FK → sites.id
version                 序号（1, 2, 3...）
status                  pending / generating / uploading / success / failed
triggered_by            user_id
cdn_paths               JSON: {"primary": "https://...", "fallback": "..."}
file_count              上传文件数
total_size_bytes        版本总大小
duration_ms             耗时
error_message           失败时的错误
enabled_languages       JSON: 发布时启用的语言（快照）
template_version        发布时用的模板版本（快照）
created_at
finished_at
```

索引：`site_id + version DESC`

**provisioning_jobs**（云资源自动化）

```
id
site_id             FK
job_type            create_bucket / bind_domain / issue_ssl / renew_ssl / cleanup
status              pending / running / success / failed / retrying
provider            aliyun / cloudflare
external_id         云上的任务 ID
attempts            重试次数
last_error          失败原因
payload             JSON 输入参数
result              JSON 输出
created_at
started_at
finished_at
```

**subscriptions**

```
id
user_id             FK → users.id
plan                free / standard / premium
status              active / past_due / canceled / trialing
billing_cycle       yearly（只支持年付）
started_at
current_period_end  下次续费 / 到期时间
canceled_at
payment_provider    alipay / wechat / stripe
created_at
updated_at
```

**payments**

```
id
user_id
subscription_id     FK → subscriptions.id
amount              金额

status              pending / succeeded / refunded / failed
payment_provider    alipay / wechat / stripe
provider_txn_id     第三方交易号
invoice_id          FK → invoices.id（可空，开票后回填）

```

**invoices**（发票）

```
id
user_id
payment_id          FK → payments.id
invoice_number      发票号
title               公司抬头

pdf_url

created_at
```

**audit_log**

```
id
user_id             可空（系统操作）

entity_type         site / user / subscription / domain
entity_id
ip_address
user_agent

created_at
```

索引：`user_id + created_at DESC`、`(entity_type, entity_id)`

**email_log**

```
id
user_id                 可空
to_email
email_type              login_link / publish_success / billing_reminder / inactive_warning / payment_receipt
subject
sent_at
delivery_status         sent / bounced / opened
provider_message_id     第三方邮件服务的消息 ID
created_at
```

**site_stats**（缓存，源在文件系统）

```
id
site_id                     FK，唯一
product_count               从 data/products.yaml 算
case_count
page_count
asset_count
last_content_modified_at    YAML 文件的最近修改时间
visit_count_30d             访问量（如果集成）
updated_at                  缓存更新时间
```

> 派生数据，主源是文件系统。用途：仪表盘显示「您有 12 个产品」、运营看板看「哪些用户在用」。

**translation_jobs**（Phase 2）

```
id
site_id
source_lang
target_lang
status              pending / running / success / failed
char_count          输入字符数
token_count         LLM 用了多少 token
estimated_cost      预估费用（¥）

started_at
finished_at
created_at
```

### 关系图

```text
users ─┬─→ sites ─┬─→ domains
       │          ├─→ publish_versions
       │          ├─→ provisioning_jobs
       │          ├─→ site_stats
       │          └─→ translation_jobs (Phase 2)
       │
       ├─→ subscriptions ──→ payments ──→ invoices
       │
       ├─→ login_tokens
       ├─→ audit_log
       └─→ email_log

templates  （独立表，sites.template_name 引用其 name）
```

### MVP 子集

跑 M1-M3 只需要这 4 张表：`users`、`login_tokens`、`sites`、`templates`

到 M5 加：`publish_versions`、`provisioning_jobs`、`domains`、`audit_log`、`email_log`

到 Phase 2 加：`subscriptions` + `payments` + `invoices`、`translation_jobs`

| 表 | 索引字段 |
|---|---|
| `users` | `(email)` |
| `login_tokens` | `(token_hash)`, `(email, used_at)` |
| `sites` | `(owner_id)`, `(slug)`, `(status)` |
| `domains` | `(hostname)`, `(site_id)` |
| `publish_versions` | `(site_id, version DESC)`, `(status)` |
| `provisioning_jobs` | `(site_id, status)`, `(job_type, status)` |
| `subscriptions` | `(user_id, status)` |
| `payments` | `(user_id, created_at DESC)` |
| `audit_log` | `(user_id, created_at DESC)`, `(entity_type, entity_id)` |
| `email_log` | `(user_id, created_at DESC)` |

### 关键设计决策

- 主键用 BIGSERIAL（不是 UUID）：简单、紧凑、SQLite 友好。URL 里不暴露主键，用 slug 替代
- 站点删除用软删除（30 天可恢复），login_tokens 定期清理
- JSON 字段只在数组/稀疏结构场景使用，不滥用当 schemaless 偷懒
- URL 用 `slug`（URL-friendly 字符串），平台可切换 subdomain / path 模式不动 DB
- 数据库选型：MVP 用 SQLite，规模化换 PostgreSQL，用 SQLAlchemy ORM 屏蔽差异
