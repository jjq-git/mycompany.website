## DeepSeek AI 助手

**在店主后台集成 DeepSeek AI 助手，帮助店主完成内容创作、多语言翻译、SEO 优化建议、操作引导等工作。**

### 定位

DeepSeek 是店主的"网站内容帮手"，不是代码生成器。它帮店主写产品描述、优化文案、把母语内容翻译成其他语言、解答操作疑问——但不会生成 HTML/CSS/JS。

平台创建的站点是多语言的（见 [多语言与AI翻译.md](多语言与AI翻译.md)），店主只维护一份母语内容，其余语言由本 AI 助手翻译。**翻译就是 AI 助手的核心职责之一**，和"写文案"用的是同一个 DeepSeek，不另起一套引擎。翻译的三层策略（词汇表 / 人工覆盖 / AI 自动）、Hash 缓存、`translation_jobs` 任务记录等引擎细节见 [多语言与AI翻译.md](多语言与AI翻译.md)，本节只描述 AI 助手如何承接翻译。

### 接入方式

| 维度 | 方案 |
| --- | --- |
| API | DeepSeek API（`api.deepseek.com`），Chat Completions 接口 |
| 模型 | `deepseek-reasoner`（默认，推理能力强，适合内容创作和 SEO 分析） |
| 调用方式 | 后端代理（Flask 路由转发），API Key 存在 `.env`，不暴露给前端 |
| 上下文注入 | 每次请求携带当前站点信息（公司名、行业、已有产品列表摘要），让 AI 了解业务背景 |

```text
店主输入 → 前端 JS → Flask /api/ai/chat → DeepSeek API
                                              │
                              System Prompt 注入站点上下文:
                              "你是XX公司的网站内容助手，
                               该公司是制造业企业，
                               主营智能门锁和传感器..."
                                              │
                              DeepSeek 回复 → Flask → 前端展示
```

### System Prompt 设计

```text
你是 "mycompany.website" 平台的 AI 助手，帮助小企业老板建设和管理他们的展示型网站。

你的职责：
- 帮店主撰写和优化产品描述、公司简介、博客文章
- 把店主的母语内容翻译成站点启用的其他语言（保持语气一致、尊重词汇表的固定译法）
- 给 SEO 标题和描述建议
- 解释后台功能怎么用
- 回答网站建设相关的问题

你不能做的：
- 生成或修改 HTML/CSS/JS 代码
- 访问店主未授权的数据
- 执行发布、删除等操作

当前上下文（自动注入）：
- 公司名：德恩基电子科技
- 行业：制造业
- 已有产品：12 个（智能门锁、传感器模组...）
- 当前编辑：首页 / Hero Banner 模块
- 母语：简体中文；启用语言：简体中文 / 繁体中文 / English
- 词汇表（固定译法，翻译时必须遵守）：智能门锁→Smart Door Lock，德恩基电子→Dengtech Electronics
```

### 各场景的 AI 入口

| 位置 | 触发方式 | AI 知道什么上下文 | 典型用途 |
| --- | --- | --- | --- |
| **右下角悬浮按钮**（主入口） | 点击打开对话面板 | 全站概况（公司名、行业、产品数、启用语言） | 通用问答、操作疑问、内容建议 |
| 产品编辑页 → "AI 写描述" 按钮 | 点击按钮 | 当前产品名称、已填字段 | 根据产品名自动生成描述文案 |
| 首页 → 模块配置面板内 | 配置面板底部 "AI 建议" | 当前模块类型、已有内容 | 帮 Banner 写标题、帮特色区写卖点 |
| **多语言页 → "一键翻译" 按钮** | 点击按钮选目标语言 | 母语内容全文、词汇表、行业 | 把整站母语内容批量翻译到目标语言 |
| **翻译结果逐条编辑 → "重译" 按钮** | 点击某条译文旁的按钮 | 该条源文本、上下文、词汇表 | 对单条不满意的译文重新翻译 |
| 仪表盘卡片 | 页面加载时显示 | 全站概况 | "您的 12 个产品没有填写 SEO 简介，要帮您生成吗？" |
| 发布前检查失败时 | 检查结果面板 | 缺失字段列表、各语言翻译完整度 | "英文版有 5 处未翻译，要我帮您补齐吗？" |

### 典型对话场景

#### 场景1：帮店主写产品描述

```text
店主: 帮我的"智能门锁 Pro"写一段产品描述

AI（上下文: 制造业，已有产品名"智能门锁 Pro"）:
这里是一段产品描述建议：

---
智能门锁 Pro 采用先进的指纹识别技术，0.3 秒快速解锁。
支持密码、指纹、手机 APP 三种开锁方式，适配各类门型。
IP65 防水等级，适合户外安装。已通过公安部安全认证。

主要卖点：
• 0.3 秒指纹解锁
• 三种开锁方式
• IP65 防水
• 公安部认证
---

要我把这段填到产品描述里吗？[一键填入]
```

#### 场景2：SEO 建议

```text
店主: 看看我网站有什么 SEO 问题

AI（读取当前站点数据）:
你的网站有 3 个可以改进的地方：

1. ⚠️ 首页 Banner 用的是模板默认标题，建议改成公司名或核心业务
2. ⚠️ 12 个产品中有 8 个没填简介（搜索排名受影响）
3. ✅ sitemap.xml 已正确生成
4. ✅ 所有图片已自动转 WebP

要我帮你逐一处理吗？
```

#### 场景3：操作指引

```text
店主: 怎么加一个新页面？

AI:
在左侧点击"菜单配置" → 点"+ 添加菜单项" → 
填菜单名（如"服务"）→ 选类型为"list"或"page" → 
目标填"services" → 保存。

系统会自动生成 /services 页面。
你可以在菜单列表里点"服务"→ 选模块填内容。

需要我帮你创建一个"服务"菜单吗？[一键创建]
```

#### 场景4：多语言翻译

```text
店主: 把我的网站翻译成英文

AI（上下文: 母语简中，目标英文，词汇表已注入）:
好的，我会把首页、产品、关于、联系等所有母语内容翻译成英文。
按词汇表的固定译法处理（"智能门锁"→"Smart Door Lock"），
已翻译过且没改动的内容会跳过，只翻新增和改过的部分。

预计翻译 38 段文本，约 1200 字，需要约 10 秒。

[开始翻译]  [先看看会翻哪些内容]

——翻译完成后——
✅ 已翻译 38 段。其中：
• 3 段命中词汇表，按你的指定译法处理
• 2 段你之前手动改过，已保留不动
• 1 段我拿不准（产品型号 "DK-9 Pro"），建议你确认

要逐条检查译文吗？[查看翻译] [直接保存]
```

> 翻译的引擎逻辑（三层策略、Hash 缓存、增量翻译、`translation_jobs` 记录）见 [多语言与AI翻译.md](多语言与AI翻译.md)。本场景描述的是店主视角的对话交互，AI 助手是其中"第三层 AI 自动翻译"的执行者。

### 数据流与安全

| 维度 | 做法 |
| --- | --- |
| API Key | 存 `.env` 的 `DEEPSEEK_API_KEY` 变量，通过 Flask 后端环境变量读取，**绝不提交到 git** |
| 数据发送 | 仅发送站点的公开内容（产品名、公司名、已填字段、待翻译文本），不发送密码/邮箱 |
| 翻译数据量 | 整站翻译会批量发送母语内容，按 Hash 缓存只发新增/改动部分（见 [多语言与AI翻译.md](多语言与AI翻译.md#hash-缓存只翻译改过的内容)），避免重复消耗 token |
| 速率限制 | 每店主每 30 秒最多 5 次请求（防滥用和费用失控）；整站翻译作为一个批量任务计一次，不逐条触发 |
| 日志 | 对话请求记录到 `audit_log`（action=ai_chat）；翻译任务另记到 `translation_jobs` 表（见数据库设计） |
| 费用控制 | 月预算上限（如 ¥50/店主/月），对话与翻译共用同一额度，超限后提示"AI 助手本月使用额度已用完" |

### 数据库扩展

新增 `ai_chat_log` 表：

```
id               主键
site_id          站点 ID
user_id          店主 ID
role             user / assistant / system
content          消息内容
token_count      消耗 token 数
model_used       deepseek-chat / deepseek-reasoner
created_at
```

### 实施阶段

| 阶段 | 内容 |
| --- | --- |
| M4（基础版） | 右下角悬浮按钮 + 对话面板，通用问答，接入 DeepSeek API |
| M4+（场景版） | 产品编辑页 "AI 写描述" 按钮、模块配置面板 "AI 建议" 按钮 |
| M5（主动版） | 仪表盘卡片主动提示、发布前检查推荐 AI 修复 |
| Phase 2（翻译） | 复用同一 DeepSeek 接入，承接多语言"一键翻译"与单条"重译"；与 [多语言与AI翻译.md](多语言与AI翻译.md) 翻译引擎章节对接 |

> 翻译能力随多语言（Phase 2）一起上线，但底层就是 M4 已接入的 DeepSeek，不重复搭建。
