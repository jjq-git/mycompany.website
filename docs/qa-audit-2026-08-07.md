## 一、已修复（已落盘，本次提交）

### 1. 模块变体名被污染成字符串 "None"

**链路**：

```
种子数据 variant: null                    → Python None
  ↓ panel_page_edit.html {{ ... | default('default') }}
Jinja default() 只处理 undefined，不处理 None → 界面渲染出 "None"
  ↓ 同样写法的 hidden input
点一次保存就把字符串 "None" 回写进 YAML
```

**修复**：`| default('default')` 改为 `or 'default'`（与 JS 版 `variant || 'default'` 对齐）；claude 模板 3 个 `home.yaml` 共 36 处 `variant: null` 改为 `variant: default`。

**前台不受影响** —— `builder.py` 找不到 `variants/None.html` 会回退 `template.html`，渲染结果正确。但它污染数据、后台显示错误、影响变体切换的回显，且 `builder.py:2427` 的 `variant in (None, '', 'default')` 判断没包含字符串 `'None'`，被污染的模块会走不同分支。

### 2. 样式变体选了完全不生效

**根因**：`applyDataPresetToModule` 对 radio 组写 `.value` 而不是 `.checked`。

样式型变体的预设（如 `style_text-align: center`）落在一组 radio 上。旧写法用 `querySelector` 只拿到第一个选项，再直接改它的 `value`，后果是：

1. 第一个选项的值被篡改（「居左」那项的 value 变成了 `right`）；
2. 仍然**没有任何 radio 被选中** —— 浏览器不提交未选中的 radio 组，样式数据整个丢失。

**实测对比**（同为 `hero_banner`）：

| 模块 | 路径 | 落盘的 data |
|---|---|---|
| module_0 | 换变体 | `{}` 全丢 |
| module_12 | 添加模块 | `{'style_text-align': 'center'}` ✓ |

**影响面已钉死**：只有「换变体」路径有问题，且换变体功能只存在于 `panel_page_edit.html`。另外三处（`page_home.html`、`panel_detail_templates.html`、`panel_data_list.html`）只有「添加模块」分支，走 `renderDynamicFieldsGrouped` 在生成 HTML 时就带上 `checked`，不受影响。

**修复后端到端验证通过**：radio 正确选中 → 落盘 `{'style_text-align': 'left'}` → 前台预览标题真的左对齐了。

## 四、踩过的坑（下次别重蹈）

1. **`flask` 不在 PATH** —— CLAUDE.md 第十节的命令表写的是裸 `flask --app run ...`，本机必须用 `python -m flask --app run ...`
2. **PowerShell here-string 里的 `$`** —— `\$` 不是转义（反引号才是），Python 收到的是字面 `\$`，正则会去匹配真的 `$` 字符。连续两次「替换 0 处」都是这个原因。**复杂正则一律写成脚本文件执行，不用 `python -c` 拼**
3. **YAML 里 `variant: None` 不是 null** —— `None` 不是 YAML 的 null 关键字（只有 `null` / `~` / 空 才是），所以它是**字符串**，但肉眼看文件极容易误判成空值
4. **CRLF 与正则** —— 种子数据是纯 CRLF。用 `newline=''` 保换行符时，行尾的 `\r` 会挡住 `[ \t]*$` 这类正则；用零宽前瞻 `(?=\r?$)` 既匹配得上又不消费 `\r`
5. **`/_panel/home` 直接访问没样式** —— 那是 panel 片段，设计上要嵌在 iframe 里，不是 bug
6. **Grep 结果被截断却当成完整结果 —— 本次最贵的教训**。返回里带 `[Showing results with pagination = limit: N]` 就说明**还有没显示的匹配**，此时「列表里没有 X」**不等于** 「X 不存在」。这个错误本次犯了两次：一次让我误判 `onBlockPaletteConfirm` 只存在于三个文件（实际四个），一次让我误判 claude 模板没有汉堡按钮，并把这个错误结论写进文档、memory 和 git 提交信息，直到用户拿手机截图才推翻。**规矩：凡是要下「某文件/某模板没有 X」这种否定结论，必须对该文件单独 Grep 复查一次，不能只看批量搜索的结果。**
7. **浏览器实测优先于代码推断** —— 上面那个误报，本可以在实时预览里被更早发现；反过来，实时预览里「header 只有 logo」也不能直接推断成「模板没有汉堡按钮」。两种证据都要，且互相印证不上时以真实构建产物为准。
