# 发布、输出结构、优化、自定义口子

## 一、输出目录结构（CDN 上的样子）

每个店主网站发布后在 CDN 上的样子（多语言示例）：

```text
company_a.com/
├── index.html              ← 根：自动按浏览器语言重定向到 /en/ 或 /de/
│
├── en/                     ← 英文整站（自包含）
│   ├── index.html
│   ├── about.html
│   ├── contact.html
│   ├── products/
│   │   ├── index.html      ← 列表页（含筛选/分页 JS）
│   │   ├── data.json       ← 列表用数据（精简字段）
│   │   ├── product_1.html  ← 详情页（预生成，SEO）
│   │   └── ...
│   ├── images/             ← 英文站用的图
│   ├── files/              ← 英文规格书等
│   ├── videos/             ← 英文站的自托管视频
│   ├── css/
│   ├── fonts/              ← 子集化后的英文字体
│   └── js/
│
├── de/                     ← 德文整站（同样结构，资源完全独立）
│   └── ...
│
├── sitemap.xml             ← 含所有语言所有 URL + hreflang 信息
└── robots.txt
```

**核心原则：每个语言目录是自包含的整站，没有共享资源目录**。
单语言导出 = 复制 `/en/` 一个文件夹就能跑。

## 二、资源的语言策略：全部按语言分

**所有资源都按语言完全复制**，不做"是否共享"的判断。

| 资源类型   | 策略                           |
| ---------- | ------------------------------ |
| HTML 页面  | 按语言分                       |
| data.json  | 按语言分                       |
| 图片       | 按语言分（多数语言相同也复制） |
| PDF / 文档 | 按语言分                       |
| 视频       | 按语言分                       |
| 字体       | 按语言分（英文不需要中文字体） |
| CSS / JS   | 按语言分                       |

理由：

- 100MB 储存成本 ≈ ¥0（OSS / R2 都是分钱级别）
- 心智模型统一：每个语言目录就是一个完整网站
- 单语言导出 / 自托管极简
- 不用维护"哪些文件按语言、哪些共享"的判断逻辑

### 上传大小限制

| 类型       | 单文件上限 |
| ---------- | ---------- |
| 图片       | 5 MB       |
| PDF / 文档 | 20 MB      |
| 视频       | 50 MB      |

视频限制 50 MB 是关键：

- 50MB × 启用语言数 ≤ 200MB（4 语言以内可控）
- 超过 50 MB 的视频强制要求**外链 YouTube / 腾讯视频 / B 站**
- 既保护储存与带宽，也保护店主体验（自托管大视频加载慢）

> 小企业网站典型规模：< 100 MB（不含视频）。
> 即使全部资源按语言复制 3 份，也只是 ¥几分钱/月的储存成本。
> **简单 > 优化**（详见 [vision.md](vision.md) 信念 5）。

## 三、列表页 vs 详情页：渲染策略

数据块（产品列表、案例集等）输出**混合结构**：

| 输出       | 形式                              | 用途                     |
| ---------- | --------------------------------- | ------------------------ |
| **详情页** | 每个条目一个预生成 HTML           | SEO 关键，被搜索引擎抓取 |
| **列表页** | 一个 HTML + data.json + 浏览器 JS | 处理筛选、排序、分页     |

### 为什么这样分

- **详情页必须预生成**：访客通过 Google 搜"智能门锁 Pro"应直接命中详情页，JS 渲染抓不到内容
- **列表页用 JS 是合理的**：列表本身不靠 SEO，且交互需求（按分类筛、按价排序、搜索框、翻页）天然动态。预生成所有组合 = 文件爆炸

### 这还算"静态网站"吗？算

「静态」指的是 **没有后端运行时**，不是「没 JS」：

- JS 是静态资源，CDN 直接给
- data.json 是静态文件，CDN 直接给
- 所有逻辑在浏览器里跑
- 平台死了，整套照样跑

### 一份数据，多份输出

数据源只有一份 `products.yaml`（含全部字段）。生成器**按需挑字段**：

```text
sites/<id>/data/products.yaml （含全部字段）
        │
        ├── 抽 preview 字段 → /en/products/data.json
        │   只含 id / name / image / summary / price / category
        │
        └── 全部字段 → /en/products/product_1.html ... product_50.html
            含 description / specs / gallery 等完整内容
```

50 个产品 → 1 个列表 HTML + 1 个 data.json + 50 个详情 HTML = **52 个文件**，
无论店主怎么筛、访客怎么翻页都够用。

### 访客体验

```text
访客访问 /en/products/
    ↓
浏览器加载 index.html (5KB) + data.json (25KB)
    ↓ 几十毫秒
列表显示，含筛选/分页 UI
    ↓
点「下一页」 → JS 切片 → 立刻显示，零网络请求
点某分类 → JS 过滤 → 立刻显示，零网络请求
点某产品 → 跳转 product_5.html → CDN 给 SEO 友好的详情页
```

## 四、发布的完整流程

店主点「发布」按钮后：

```text
1. 检查必填项（公司信息、至少 1 个产品等）
        ↓
2. 读取站点文件夹（sites/<id>/ 下的所有 yaml + 资源）
        ↓
3. 对每种启用的语言，分别渲染：
   - 静态页面（index、about、contact）
   - 数据块详情页（每个产品一个 html）
   - 数据块列表页（一个 html + 一个 data.json）
        ↓
4. 优化资源（按语言）：
   - 字体子集化（扫描该语言的所有字符）
   - 图片确认已是 WebP（上传时已处理）
   - CSS / JS 压缩
        ↓
5. 生成附属文件：
   - sitemap.xml（含所有语言所有 URL + hreflang）
   - robots.txt
   - 根 index.html（语言重定向）
        ↓
6. 上传到 CDN（增量上传，只传变化的文件）
        ↓
7. 更新店主网站的「最新版本」指针
        ↓
8. 显示访问 URL
```

中等规模站（30 页 + 50 产品 + 双语言）应在 10-20 秒内完成。

## 五、字体子集化（关键差异化）

中文字体动辄 5-10 MB。访客打开网站要等几秒下载字体，体验很糟。

我们的方案：发布时扫描所有页面，**统计实际用到的所有字符**，从字体文件中提取这些字符做成一个小字体（一般 10-30 KB）。

| 方式             | 字体文件大小 | 首屏字体加载   |
| ---------------- | ------------ | -------------- |
| 直接用完整字体   | 9.4 MB       | 3-8 秒         |
| 用系统字体凑合   | 0            | 立刻（但难看） |
| **我们：子集化** | **15 KB**    | **< 0.1 秒**   |

注意：

- **每次发布都重新生成字体**（店主可能加了新字符）
- **按语言分别子集化**（英文不需要中文字体）
- 不做缓存（避免"新加的字显示成方块"的灵异 bug）

### 字体版权

国内字体诉讼凶猛（方正、汉仪等专门起诉商用网站）。
**平台只允许使用明确可商用的字体**：

| 字体                | 来源                | 风格          |
| ------------------- | ------------------- | ------------- |
| 思源黑体 / 思源宋体 | Adobe + Google 开源 | 通用，最稳    |
| 阿里巴巴普惠体 2.0  | 阿里巴巴            | 现代商务      |
| OPPO Sans           | OPPO                | 圆润现代      |
| 站酷系列            | 站酷                | 设计感        |
| HarmonyOS Sans      | 华为                | 简洁现代      |
| 霞鹜文楷            | 开源                | 文艺 / 书法感 |

**绝对不能上的**：方正、汉仪、华文、文鼎、造字工房（专门钓鱼起诉）。
不允许店主上传自定义字体（避免版权连带责任）。

## 六、图片处理

图片**在店主上传时就处理**（不在发布时）。

| 用途             | 尺寸        | 格式 |
| ---------------- | ----------- | ---- |
| 缩略图（卡片用） | 600 × 450  | WebP |
| 中图（详情用）   | 1200 × 900 | WebP |
| 原图（备份）     | 原始尺寸    | WebP |

旧浏览器 fallback 提供 JPEG。

发布时图片复制到每个启用语言的 `images/` 目录（按上面的资源策略）。

## 七、CDN

MVP 阶段使用**阿里云 OSS + CDN**（详见 [infrastructure.md](infrastructure.md)）。
不做多 CDN 抽象层 —— 复杂度提前透支。

将来真有跨地域客户需求，加 Cloudflare 作为高级版选项（数据库 `sites.cdn_provider` 字段已留好）。

## 八、四个自定义口子

我们不让店主改 HTML / CSS，但开放四个明确的口子，满足"我想动一下"的需求。

> 哪些档位能用：
>
> - 自定义 HTML 块、整站 ZIP 导出 → 全档位
> - 全站 head 注入、全站自定义 CSS → 高级版（详见 [vision.md](vision.md) 商业模式）

### 口子 1：自定义 HTML 块

块库中有一个特殊块叫「自定义 HTML」。店主可以加到任何页面，里面粘贴自己的代码（公众号二维码、第三方插件等）。

- 自动加 `.custom-html-block` CSS 容器，避免污染其他块
- 默认禁用 `<script>`，需要手动勾选「我要插入脚本」
- 弹出提示："自定义代码出问题平台不负责"

### 口子 2：全站 head 注入

设置中有一个文本框「在 `<head>` 中插入的代码」。
专门给百度统计、Google Analytics、客服系统使用。

### 口子 3：全站自定义 CSS

设置中有一个 CSS 编辑框，注入到每个页面末尾。
店主能写 `.my-section { color: red; }` 之类的小调整。

### 口子 4：导出整站 ZIP

允许店主下载整个静态网站。

**这是信任锚点**：店主知道随时能跑路，反而留下来。
也是真正的"开发者模式"：想改？下载下来自己改。

### 为什么是这四个

不开放完整的"开发者模式"，原因：

| 维度     | 不做开发者模式       | 做了开发者模式                           |
| -------- | -------------------- | ---------------------------------------- |
| 数据存储 | 块只存「字段值」     | 必须同时存「字段值」和「自定义代码」两套 |
| 模板升级 | 自动让所有用户受益   | 用户动过的部分无法升级                   |
| 故障归因 | 出问题肯定是平台 bug | "是我代码问题还是平台 bug？" 互相甩锅    |
| 安全     | 用户输入都是文本     | XSS / 黑帽 SEO 风险                      |
| 客服支持 | 标准化 FAQ           | 每个用户都是独特问题                     |

完整开发者模式让系统复杂度翻倍。这四个口子能挡住 95% 的需求，复杂度只 +10%。

## 九、自定义域名

完整流程（API 自动化 + SSL 自动续期 + 错误重试）见 [infrastructure.md](infrastructure.md)。
简要流程：

- 店主在设置里输入自己的域名
- 系统调阿里云 CDN API 添加加速域名 → 给出 CNAME 配置指引
- 店主去自己的域名服务商配 DNS
- 系统检测 DNS 生效后，启动 ACME 流程向 Let's Encrypt 申请证书（90 天期）
- 证书自动上传部署到阿里云 CDN
- 续期任务每天扫描，提前 30 天自动续签

## 十、发布历史与回滚

每次发布生成一个版本快照（在 CDN 上独立目录）。

店主可以：

- 看到发布历史（"3 天前发布"、"上周二发布"）
- 一键回滚到任意旧版本

最多保留 10 个版本，更老的自动清理。

## 十一、平台关停应急

承诺给用户的"平台死了网站不死"是怎么实现的：

- 已发布的网站在 CDN 上，平台不动它们也活着
- 店主可以一键导出 ZIP（**就是 sites/<id>/ 文件夹本身**），丢到任何 CDN 都能跑
- 文档公开，未来必要时可以让用户自己部署

**这是产品最重要的信任承诺，不能妥协。**
