## 一、结论

**“创建站点 → 编辑 → 构建 → 预览 → ZIP 导出”主链路基本可用；“正式发布”链路未实现，专项验收不通过。**

当前页面主动禁用了发布入口，这是正确的保护措施。后端 `/publish` 仍然存在，但它只在临时目录构建一次，随后删除产物并把数据库状态改成 `published`；没有上传 OSS/CDN、没有切换线上版本、没有形成可回滚快照，也没有返回真实公网地址。因此该接口不能被认定为正式发布。

部署决策：

> **允许继续内部编辑、预览和 ZIP 导出；禁止开放发布按钮，禁止把 `/publish` 的成功响应当作网站已经上线。**

## 四、部署阻断项

### LIFE-P0-01 `/publish` 不执行真实发布，却写入“已发布”状态

现有实现：

1. 在 `TemporaryDirectory` 中调用 `build_site(..., base_url='')`。
2. 构建报告为空后离开临时目录，产物随即删除。
3. 设置 `site.status = 'published'` 和 `last_published_at`。
4. 返回的地址是后台 `/preview_site/<slug>`，不是公网发布 URL。

没有发现 OSS/CDN 上传、缓存刷新、线上版本指针、域名切换或持久化发布目录。页面顶栏、概览和账户站点列表已经禁用发布按钮，但登录后的所有者或管理员仍可直接 POST 该接口。

部署前修复要求：

- 在“只允许导出 ZIP”与“平台托管发布”之间明确产品方案。
- 若做托管发布，必须先持久化不可变版本，上传并校验成功后再原子切换线上指针。
- 只有外部发布及回读校验成功后才能更新 `published` 和时间；失败不得改变当前线上版本。
- 成功响应返回真实站点 URL、版本号和可追踪的发布任务/审计标识。
- 在修复完成前继续保持所有 UI 发布入口禁用，并在后端关闭或显式返回“尚未开放”。

复验标准：人为让上传、校验、切换指针分别失败，线上旧版本必须仍可访问，数据库不得假报成功；完整成功后从公网域名回读内容和资源校验通过。

### LIFE-P0-02 设计文档承诺的正式发布能力尚未落地

`docs/site/publish.md` 描述了必填检查、资源优化、OSS/CDN 增量上传、最新版本指针、发布历史和一键回滚；当前代码只实现静态构建、SEO 附属文件和链接报告，不具备其余发布能力。

尤其缺失：

- 公司信息、业务内容等发布前完整性门禁；
- 字体子集化和文档所述完整资源优化门禁；
- OSS/CDN 上传、缓存处理及公网回读；
- 不可变版本、最多保留版本数、发布历史和回滚；
- 并发发布互斥、幂等、超时、重试和任务状态；
- 发布期间编辑内容的一致性快照。

修复前，`docs/site/publish.md` 只能作为目标设计，不能作为当前功能说明或运维手册。

## 五、高优先级业务问题

### LIFE-P1-01 发布后编辑没有“未发布变更”状态

动态复现：成功调用 `/publish` 后修改公司资料，站点仍为 `published`，`last_published_at` 不变，也没有新的草稿版本或 dirty 标记。账户页会继续显示“已发布”，无法判断线上版本和编辑中内容是否一致。

同时，YAML 内容保存不会触碰 `Site.updated_at`；概览中的“最近更新”不能反映真实内容更新时间。

修复要求：把“是否曾发布”“当前线上版本”“当前草稿版本/内容版本”“是否有未发布变更”拆开建模；所有内容、设置、媒体引用和菜单变更统一触发内容版本或 dirty 状态。

### LIFE-P1-02 发布前没有业务完整性门禁

当前 `/publish` 仅以 builder 的页面/链接报告作为阻断条件，没有执行文档约定的公司资料、必要页面、必要内容、域名/托管配置等业务检查。技术上能生成 HTML 不代表业务上可上线。

修复要求：建立结构化 preflight 结果，区分错误与警告；错误阻断发布，前端逐项提供修复入口，后端不可依赖前端按钮状态绕过。

### LIFE-P1-03 非法模板名被静默替换为 Blank

篡改建站请求的 `template_name=not-a-template` 后，接口返回成功并创建 `template_name=blank` 的站点。用户选择与最终结果不一致，自动化调用也无法识别参数错误。

修复要求：提交的模板名必须是当前可见、可用且版本有效的模板；否则返回明确 4xx/表单错误，不得回退到第一套模板。只有页面首次展示时才允许给出默认选项。

### LIFE-P1-04 建站初始化失败会遗留孤儿目录

强制让种子数据复制抛错后，数据库记录成功回滚，但已经创建的 `sites/<new-id>/` 仍存在。下一次恰好复用 ID 时会被清空，但在此之前它是无数据库归属的残留目录。

此外，`copy_seed_data()` 在种子目录不存在时返回 `False`，调用方没有检查返回值，可能把仅含少量默认结构的不完整站点当作创建成功。

修复要求：文件初始化使用临时目录，完整成功后原子改名；异常时清理精确目录；缺失 seed（若模板声明必须有）应作为创建失败；增加数据库与目录补偿任务。

### LIFE-P1-05 viewer 可通过 GET 触发构建

`/build` 同时接受 GET/POST。`_current_context()` 只把非 GET 当作写操作，因此 viewer 访问 GET `/build` 会执行完整构建并返回 302，而不是 403。该动作会消耗 CPU/IO 并改写预览产物，且 GET 不受 CSRF 保护。

修复要求：构建只接受 POST，并要求 editor/owner/admin 写权限；预览若需自动构建，应使用受控、限流、可去重的内部任务，不把带副作用的动作暴露为普通 GET。

### LIFE-P1-06 部分只读 GET 路由会写 YAML

菜单 GET 在补菜单项 ID 时会写回 `settings.yaml`，旧页脚 GET 也可能执行迁移；viewer 虽然被定义为只读，进入这些页面仍可能改变文件。写时迁移也没有统一更新站点内容版本。

修复要求：迁移放到显式、可审计的升级流程，或至少要求写权限；所有 GET 保持幂等、无业务数据副作用。

### LIFE-P1-07 缺少发布快照、并发控制与可恢复边界

发布直接读取正在编辑的 YAML 和资源，没有冻结输入版本。长构建期间继续编辑可能得到跨时刻混合产物；重复点击或多实例并发也没有站点级锁、幂等键和任务状态。

修复要求：发布基于不可变内容快照，增加站点级发布锁/任务表、幂等键、超时和失败恢复；状态转换必须有明确事务边界。

### LIFE-P1-08 模板预览子资源会重复触发整站构建

Playwright 打开 Dengtec 模板预览时，页面的 `/templates/dengtec/preview/static/css/main.css` 等子资源仍进入 `template_preview()`，再次调用 `build_template_preview()`。首次实测并发复制正在读取的视频文件时触发 WinError 32，CSS 返回 500；复跑时公司 Logo 先返回 404，页面最终显示破图，同时日志出现部分语言输出路径被跳过。

这说明模板预览路由把“构建”和“读取产物”混在同一个 catch-all 路由中，浏览器并发加载资源时不具备一致性。

修复要求：模板预览构建使用锁、不可变版本目录或临时目录原子切换；子资源只读取已经完成的产物，不得每次请求都重建；构建期间旧预览保持可读，失败后不得暴露半成品。

### LIFE-P1-09 390px 移动端概览主内容被固定侧栏裁切

Playwright 截图确认：移动端仍显示约 240px 的完整左侧导航，主内容从视口右侧开始，只剩狭窄一条可见区域。页面使用 overflow 隐藏了横向滚动，因此简单 `scrollWidth` 检查会误判为无溢出，但实际操作不可用。

修复要求：小屏默认收起侧栏，提供明确的抽屉开关与遮罩；主内容宽度必须回到视口内。至少复验 320、375、390、768px 的概览、工作台、内容编辑和设置页面。

## 六、中优先级问题

### LIFE-P2-01 创建与内容编辑缺少业务审计

动态检查确认建站成功后该站点审计记录为 0。当前主要只记录账户管理、组织动作和发布；公司、主题、菜单、页面、数据集和媒体变更没有统一审计。概览“最近活动”不能完整反映建站与编辑过程。

修复要求：至少记录建站、关键设置、内容增删、媒体删改、构建/导出和发布；审计保存操作者、站点、动作、内容版本、结果和失败原因，避免保存敏感正文或密钥。

### LIFE-P2-02 模板公开元数据与业务白名单不一致

扫描得到 6 个 `is_public=true` 模板，但业务只开放 Blank、Claude、Dengtec。Airbnb、Apple、Notion 对外元数据和实际可用性不一致。正式部署前明确它们是实验模板还是产品模板，并统一元数据、列表、预览和测试范围。

### LIFE-P2-03 公司资料页存在图片错误处理加载时序异常

Chromium 捕获未处理异常：`showCompanyImageError is not defined`。图片的内联 `onerror` 可能在页面底部函数声明执行前触发。虽然文字表单仍能保存，但控制台不干净，图片错误占位逻辑可能失效。

修复要求：在图片请求前注册处理函数，或改用脚本统一绑定事件；缺图场景必须稳定显示占位和移除入口。

### LIFE-P2-04 建站 Slug 的 HTML `pattern` 在 Chromium 中无效

Chromium 控制台报告 `pattern="[a-z0-9][a-z0-9-]{1,28}[a-z0-9]"` 在新的 `v` 正则语义下字符类非法，浏览器会忽略该客户端约束。服务端校验仍生效，但前后端反馈不一致。

修复要求：转义字符类中的连字符或使用兼容表达式，并增加浏览器端合法/非法 slug 表单校验用例。
