# 详情模板

## 目的

列表菜单的数据项通常需要详情页，例如产品详情、案例详情、新闻详情。

详情模板用于定义这些详情页的渲染规则：显示哪些模块、模块怎么排列、每个模块读取数据项里的哪些字段、字段如何展示、哪些内容可以自动生成、哪些样式允许配置。

它的核心目标是：

- 用户只填数据，不写 HTML / CSS / JS
- 详情页可以复用统一结构
- 同一个列表可以有多个详情页呈现方式
- 发布结果仍然是静态 HTML，符合“不会坏的网站”的产品定位

详情模板不是自由页面编辑器，也不是让用户改代码的模板系统。它应该被限制在“系统已有模块 + 字段绑定 + 显示规则 + 受控样式配置 + 自动生成规则”的范围内。

## 入口

后台菜单配置里，如果某个菜单类型是“列表”，那么这个菜单项旁边显示“详情模板”管理入口。

建议入口文案使用：

- “详情模板”
- 或图标按钮，鼠标悬停提示“管理详情模板”

不建议直接叫“创建详情模板”，因为列表菜单通常会自动拥有一个默认详情模板，用户更多是在“管理”和“选择”，不是每次都从零创建。

## 归属关系

详情模板归属于某个列表菜单 / 数据集。

结构可以理解为：

```text
站点
  菜单
    列表菜单 products
      数据集 products
      列表页配置
      详情模板列表
        默认详情模板
        其他详情模板
```

也就是说，产品列表的详情模板只服务产品数据，案例列表的详情模板只服务案例数据。先不做全站通用详情模板，避免字段绑定和维护复杂度上升。

## 详情模板的功能

- 每个类型为“列表”的菜单都可以拥有详情模板
- 新建列表菜单时，系统自动创建一个默认详情模板
- 每个列表菜单必须有且只有一个默认详情模板
- 一个列表菜单可以有多个详情模板
- 列表数据项编辑时可以选择使用哪个详情模板
- 如果数据项没有选择模板，则使用该列表菜单的默认详情模板
- 模板可以复制，方便从默认模板派生出新模板
- 模板可以预览，用某条真实数据或示例数据渲染详情页

## 使用流程

### 新建列表菜单

1. 用户创建一个类型为“列表”的菜单，例如“产品中心”
2. 系统自动创建对应数据集，例如 `products`
3. 系统自动创建一个默认详情模板，例如“默认产品详情”
4. 用户可以先不理解模板，也能直接添加产品并发布详情页

### 编辑列表数据项

1. 用户进入某条数据，例如某个产品
2. 填写标题、封面、简介、正文、参数等字段
3. 可选：选择详情模板
4. 如果未选择，则使用默认详情模板
5. 点击预览，检查详情页效果
6. 保存并发布

### 管理详情模板

详情模板管理页需要支持：

- 新建模板
- 复制模板
- 编辑模板
- 设为默认
- 预览模板
- 删除模板

删除模板时需要检查：

- 默认模板不能直接删除，必须先设置另一个默认模板
- 正在被数据项使用的模板删除前需要提示
- 删除后，原来使用该模板的数据项可以回落到默认模板

## 模板中需要哪些？

详情模板至少需要保存这些信息：

- 模板 ID
- 模板名称
- 是否默认模板
- 所属列表菜单 / 数据集
- 模块列表
- 每个模块的排序
- 每个模块的 variant
- 每个模块的字段绑定
- 每个模块的显示规则
- 每个模块的样式配置
- 每个模块的空值处理规则
- 模板反推出的数据项字段需求
- SEO 标题绑定
- SEO 描述绑定
- 封面图绑定
- 分类 / 标签生成规则
- 创建时间
- 更新时间

更完整地说，详情模板应该管理五类配置：

```text
详情模板
  内容结构
  字段绑定
  显示规则
  样式配置
  自动生成规则
```

### 内容结构

内容结构决定详情页由哪些模块组成。

例如产品详情页可以包含：

- 顶部产品摘要
- 主图 / 预览图 / 细节图
- 产品简介
- 参数表格
- 应用场景
- 下载资料
- 相关产品
- 联系按钮

模板中保存的是模块列表和模块顺序，不是某一个产品的具体内容。

### 字段绑定

字段绑定决定模块从数据项中读取哪些字段。

例如：

```text
主图模块
  主图 -> cover
  预览图 -> preview_images
  细节图 -> detail_images

参数表模块
  参数数据 -> specs

链接模块
  链接文字 -> link_text
  链接地址 -> link_url
```

### 显示规则

显示规则决定字段如何被展示。

例如：

- 是否需要预览图
- 预览图最多显示几张
- 细节图需要几张
- 图集是否滚动
- 是否自动滚动
- 自动滚动间隔几秒
- 是否显示左右箭头
- 是否显示圆点
- 表格需要几行几列
- 表格是否显示表头
- 表格空单元格是否隐藏
- 链接是否显示
- 没有链接时是否隐藏整个链接模块
- 图片为空时显示占位图还是隐藏模块

这些配置应该使用开关、数字输入、下拉选项、颜色选择器等受控表单实现，不让用户写代码。

### 样式配置

样式配置决定模板允许用户调整的少量视觉参数。

例如：

- 普通文字颜色
- 链接字体颜色
- 标题颜色
- 按钮颜色
- 表格边框颜色
- 表格表头背景色
- 图片圆角
- 模块间距
- 内容宽度
- 对齐方式

样式配置必须是受控的。用户可以选择颜色或选项，但不能直接写 CSS。

### 自动生成规则

自动生成规则决定哪些字段可以由系统根据已有内容生成。

例如：

- 分类是否从菜单 / 数据集自动继承
- 标签是否从标题、分类、参数中自动生成
- 摘要是否从正文前若干字自动生成
- SEO 标题是否由“产品名 + 公司名”生成
- SEO 描述是否由摘要生成
- slug 是否由标题生成
- 相关产品是否按分类 / 标签自动推荐

自动生成出来的内容应该允许用户手动覆盖。这样既省事，又不会把用户锁死。

## 字段绑定

字段绑定是详情模板的核心。

例如产品数据项里有：

```text
title
summary
cover
content
price
specs
preview_images
detail_images
category
tags
link_url
```

详情模板中的模块不直接保存某个产品的真实内容，而是保存绑定关系：

```text
Hero 模块
  标题 -> title
  描述 -> summary
  图片 -> cover

正文模块
  内容 -> content

参数模块
  参数列表 -> specs

图集模块
  预览图 -> preview_images
  细节图 -> detail_images

分类标签模块
  分类 -> category
  标签 -> tags
```

这样同一个详情模板可以渲染所有产品。换产品时，页面结构不变，只是字段数据变了。

## 产品详情模板示例

以产品“LED 灯条”为例。

产品数据项保存具体内容：

```text
title: LED 灯条
summary: 柔性低压灯带，适合展柜、家装和商业照明
cover: /uploads/led-strip-cover.webp
preview_images:
  - /uploads/led-strip-preview-1.webp
  - /uploads/led-strip-preview-2.webp
detail_images:
  - /uploads/led-strip-detail-1.webp
  - /uploads/led-strip-detail-2.webp
  - /uploads/led-strip-detail-3.webp
specs:
  功率: 12W/m
  电压: DC 24V
  色温: 3000K / 4000K / 6000K
category: LED 照明
tags:
  - LED
  - 灯条
  - 低压照明
link_url: https://example.com/download/led-strip.pdf
```

详情模板保存展示规则：

```text
模板：产品详情模板 A

顶部摘要模块
  标题字段 -> title
  描述字段 -> summary
  封面图字段 -> cover

产品图集模块
  启用预览图：是
  预览图字段 -> preview_images
  预览图最多显示：4 张
  细节图字段 -> detail_images
  细节图最多显示：6 张
  是否滚动：是
  自动滚动：是
  自动滚动间隔：3 秒
  显示箭头：是
  显示圆点：是

参数表模块
  数据字段 -> specs
  表格列数：2
  最多行数：8
  显示表头：否
  空字段处理：隐藏该行

资料链接模块
  是否显示：有 link_url 时显示
  链接字段 -> link_url
  链接文字：下载产品资料
  链接颜色：#0f66d0

文本样式
  普通文字颜色：#333333
  标题颜色：#111111

分类标签
  分类字段 -> category
  标签字段 -> tags
  没有标签时：根据 title、category、specs 自动生成
```

最终渲染时，模板负责“怎么展示”，产品数据负责“展示什么”。

## 模板反推字段需求

详情模板会决定某类数据项需要哪些字段。

例如某个产品详情模板启用了：

- 预览图
- 细节图
- 参数表
- 下载链接
- 自动标签

那么产品数据编辑表单里就应该出现对应字段：

- `preview_images`
- `detail_images`
- `specs`
- `link_url`
- `tags`

这意味着模板和数据表单之间需要有联动：

- 模板启用某个模块后，数据项编辑表单显示对应字段
- 模板关闭某个模块后，数据项编辑表单可以隐藏不再需要的字段
- 已有数据不要删除，只是隐藏或标记为未使用
- 多个模板同时存在时，数据项表单应该显示“当前模板需要的字段”
- 如果数据项切换模板，需要提示哪些字段会新增、哪些字段暂时不显示

这个能力很重要，因为老板用户不应该看到一大堆永远用不到的字段。

## 配置项类型

为了避免模板系统变成写代码，所有模板配置都应该落到有限的控件类型里。

建议支持这些配置类型：

- 开关：是否启用预览图、是否显示箭头
- 数字：图片数量、滚动秒数、表格行数、表格列数
- 选项：布局方式、对齐方式、图片比例
- 颜色：文字颜色、链接颜色、按钮颜色
- 字段选择：这个模块绑定哪个数据字段
- 图片字段：单图或多图
- 列表字段：参数表、标签、图集
- 文本：按钮文字、默认链接文字
- 条件显示：有值时显示、无值时隐藏

不提供：

- 自定义 CSS 输入框
- 自定义 HTML 输入框
- 自定义 JS 输入框
- 任意表达式编辑器

## 空值和异常处理

详情模板必须定义空值处理，否则静态页面很容易出现破碎区域。

常见规则：

- 必填字段为空：数据项编辑页提示用户补充
- 可选字段为空：隐藏对应模块或隐藏对应行
- 图片为空：隐藏图片区域或显示默认占位图
- 链接为空：隐藏链接按钮
- 表格某一行为空：隐藏该行
- 图集数量不足：按已有图片显示，不补空位
- 自动生成失败：保留为空，并允许用户手动填写

每个模块应该有默认空值策略，避免用户每次都要理解这些细节。

## 分类和标签

分类和标签建议分开处理。

分类更像结构信息，通常应该来自：

- 当前列表菜单
- 数据集字段
- 用户手动选择

标签更像辅助信息，可以自动生成：

- 从标题提取
- 从分类继承
- 从参数表关键词提取
- 从用户手动填写的标签合并

建议规则：

- 分类可以自动继承，但允许手动覆盖
- 标签可以自动生成，但允许手动增删
- 自动标签不应该每次保存都强行覆盖用户修改
- 可以记录哪些标签是自动生成，哪些是用户手动添加

## SEO 规则

详情模板应该负责默认 SEO 规则。

例如：

```text
SEO 标题：{title} - {site_name}
SEO 描述：优先使用 summary，没有 summary 时从 content 自动截取
SEO 图片：优先使用 cover，没有 cover 时使用第一张 preview_images
```

SEO 规则也应该允许数据项手动覆盖。

## 数据项中的模板选择

每条列表数据项可以保存一个 `template_id`。

```text
product_item
  title: "LED 灯带"
  slug: "led-strip"
  template_id: "product-detail-a"
```

如果 `template_id` 为空，则使用所属列表菜单的默认详情模板。

切换模板时需要注意：

- 不删除原有数据
- 新模板需要的字段如果缺失，提示用户补充
- 旧模板使用但新模板不用的字段可以保留，只是在当前编辑表单中隐藏
- 预览时用当前模板即时渲染

## 默认模板规则

- 每个列表菜单必须有一个默认详情模板
- 新建列表菜单时自动生成默认详情模板
- 默认模板可以被替换
- 设置新默认模板后，未指定模板的数据项自动使用新的默认模板
- 默认模板不能直接删除，除非先指定新的默认模板

## 和现有页面模块的关系

详情模板应该复用现有模块系统。

它和普通页面编辑的区别是：

- 普通页面模块保存的是页面自己的内容
- 详情模板模块保存的是字段绑定关系

例如普通页面里的 Hero 标题可能直接保存：

```text
专业 LED 照明制造商
```

而详情模板里的 Hero 标题应该保存：

```text
绑定字段：title
```

渲染详情页时，再从具体数据项中读取 `title` 的值。

因此现有模块需要逐步支持两种模式：

```text
普通页面模式
  字段值 = 直接内容

详情模板模式
  字段值 = 数据字段绑定 + 显示规则
```

同一个模块可以在普通页面里显示固定内容，也可以在详情模板里读取数据项字段。

## 限制

为了符合产品定位，详情模板需要限制范围：

- 用户不能编辑 HTML
- 用户不能编辑 CSS
- 用户不能编辑 JS
- 不引入 Grapes.js 这类整页可视化编辑器
- 不做自由拖拽布局系统
- 不做全站通用动态模板语言
- 不允许模板直接破坏静态发布结果

用户可以做的是：

- 选择模块
- 调整模块顺序
- 选择模块 variant
- 绑定字段
- 配置显示规则
- 配置系统允许的样式项
- 配置自动生成规则
- 预览效果

## 第一阶段建议

MVP 阶段可以先做小一点：

- 只支持列表菜单拥有详情模板
- 每个列表菜单自动创建一个默认详情模板
- 支持多个详情模板
- 数据项支持选择模板
- 模板编辑复用现有模块编辑能力
- 先支持常见字段绑定：文本、图片、富文本、列表、链接
- 先支持常见显示规则：是否显示、数量限制、滚动开关、自动滚动秒数、表格行列、空值隐藏
- 先支持少量样式配置：文字颜色、链接颜色、按钮颜色、图片比例、对齐方式
- 先支持基础自动生成：slug、摘要、SEO 标题、SEO 描述、标签建议
- 暂不做跨列表复用模板
- 暂不做复杂条件显示，只做“有值显示 / 无值隐藏”
- 暂不做用户自定义字段类型的高级校验
- 暂不做任意公式和表达式
- 暂不做用户自定义 CSS

第一阶段目标不是做一个强大的模板系统，而是让“列表页 + 详情页”成为完整闭环。
