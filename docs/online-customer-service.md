# 在线客服 —— 方案文档

> 状态：待实施
> 适用模板：`claude`、`dengtec`（其余模板不动）
> 关联信念：核心信念 2（用户填表不写代码）、4（平台死了网站不能死）、6（简单 > 优化）

## 一、要解决的问题

德恩基的访客其实是两拨习惯完全不同的人：

| 客户 | 习惯 | 最优接待方式 |
|---|---|---|
| 海外外贸客户 | 网页 live chat、WhatsApp | 网页聊天窗，消息推到老板手机 |
| 国内制造业客户 | 扫码加微信 | 微信二维码，不需要聊天窗 |

单一网页聊天窗对国内客户"隔靴搔痒"——他们只想扫码。所以方案是**双入口**，不是单一工具。

## 二、选型：两套方案并列

> **关键前提**：以下两套方案在**技术实现上完全相同**——都走第三节的"通用自定义代码注入"口子，区别只在老板往框里粘谁的 `<script>`。所以选 A 还是 B **不影响开发工作量**，代码一次做好，两套都能跑，以后随时换。

### 方案 A：免费方案（Tawk.to + 微信二维码）

| 客户 | 工具 | 成本 | 为什么选它 |
|---|---|---|---|
| 海外 | **Tawk.to** 网页聊天窗 | 完全免费 | 无限坐席/对话，有手机 App（老板低频登后台，消息直推手机）。彻底免费，靠卖代运营坐席盈利，不靠限制功能 |
| 国内 | **微信二维码** 悬浮入口 | 零成本、零第三方 | 国内客户就认扫码；不依赖任何 SaaS，反而最符合"平台死了网站不能死" |

- **为什么海外不选 Crisp**：Crisp 免费版限 2 坐席，超了付费。要"完全免费"则 Tawk.to 更合适。代价是聊天窗底部有 Tawk.to 小 logo（去掉 $19/月），展示型站点可接受。
- **为什么国内不用第三方聊天**：国内网页客服免费版限制多、广告味重，而国内客户真正的习惯是扫码加微信。放一张二维码图即是最优解。

#### 「微信客服」的三种含义 —— 别混淆免费情况

"微信客服"是个容易被搞混的词，实际有三种，成本完全不同：

| 说法 | 是什么 | 成本 |
|---|---|---|
| ① **微信二维码**（方案 A 国内默认） | 放一张个人/企业微信二维码图，访客扫码加你 | ✅ 完全免费、零第三方 |
| ② **微信客服（腾讯官方功能）** | 腾讯官方能力，访客网页点一下直接拉起微信聊天，消息进企业微信 | ⚠️ 功能腾讯不收费，但需**企业微信 + 微信认证**，认证费 **300 元/年** |
| ③ **第三方系统的微信渠道** | Udesk/美洽等把微信消息聚合进它后台 | ❌ 属第三方付费套餐功能，见方案 B |

**国内一路的两档选择：**

- **默认（纯免费）**：用 ①微信二维码。零成本、零依赖，最符合"平台死了网站不能死"。若你只要"访客能加上微信"，到此为止即可。
- **进阶（体验更好）**：用 ②腾讯官方微信客服。访客点一下直接开聊，不必先截图再扫码；消息统一进企业微信、手机可回。代价是认证 300 元/年。接入方式与其它第三方一致——企业微信后台拿到接入代码，粘进"自定义代码注入"框即可，**代码不用改**。

> 两档都和海外的 Tawk.to 聊天窗不冲突，可同时存在。

### 方案 B：付费方案（Udesk 一套搞定）

| 项 | 说明 |
|---|---|
| 工具 | **Udesk（客服通）** 网页插件 |
| 成本 | 商用付费，按坐席/年收费，通常几千元/年起；免费版有限 |
| 覆盖 | 国内客户为主、愿为客服体验付费时最合适 |
| 优势 | 国内服务器不卡、原生中文；工单 + 机器人 + 多渠道聚合（微信公众号/小程序/电话进同一后台）；**可同时替代"网页聊天 + 微信二维码"两个入口** |
| 接入 | 同样是它给的一段 `<script>` 网页插件代码，粘贴到"自定义代码注入"框即可，一行代码不用改 |

### 怎么选

| 你的情况 | 选 |
|---|---|
| 只要免费、海外客户为主 | **方案 A** |
| 国内客户为主、愿为完整客服体系付费 | **方案 B（Udesk）** |
| 拿不准 | 先上**方案 A** 跑通流程；因注入口是通用的，以后换 Udesk 只需重新粘一段代码，**零重构** |

> Udesk 也可以和微信二维码并存——用 Udesk 接网页实时咨询，微信码留给习惯扫码的国内客户。两者不冲突。

## 三、技术方案：通用"自定义代码注入" + 微信二维码

不为某一家客服写死逻辑，做一个**通用的页脚自定义代码字段**。老板从任意第三方客服（Tawk.to、Udesk 等）复制那段 `<script>` 粘贴进后台文本框，系统注入到全站 `</body>` 前。正因为注入口是通用的，换客服供应商时只需重新粘一段代码、零重构；同一个口子以后也能放百度统计 / GA —— 一次投入，多处复用（信念 6）。

微信二维码是独立的一小块：上传二维码图片 + 一个悬浮按钮，点击弹出图片，纯静态，零第三方。

### 数据结构（settings.yaml 新增）

```yaml
# 在线客服 / 自定义代码（跨语言共享，不分语言目录）
customer_service:
  # 海外：粘贴 Tawk.to 等第三方客服的完整 <script> 代码，注入到全站 </body> 前
  body_end_code: |
    <!--Start of Tawk.to Script-->
    <script type="text/javascript">...</script>
    <!--End of Tawk.to Script-->
  # 国内：微信悬浮入口
  wechat:
    enabled: true
    qrcode: /assets/uploads/wechat-qrcode-xxx.webp   # 上传的二维码图片
    label: 微信咨询                                    # 悬浮按钮文字
```

> 放在顶层 `customer_service`（与 `contact`、`social` 平级）。跨语言共享，不进 `xxx_zh-CN` 分语言键 —— 客服代码和二维码三语一致。

### 悬浮块 UI（注入到 `</body>` 前）

右下角一个客服区，与现有"回到顶部"按钮（`.back-to-top`）错开位置：

```
┌─────────────┐
│  💬 在线咨询  │  ← Tawk.to 自己的浮窗（它的 script 自带）
└─────────────┘
┌─────────────┐
│  📱 微信      │  ← 点击弹出二维码图片（我们注入的静态块）
└─────────────┘
```

- Tawk.to 浮窗由它的 `<script>` 自己渲染，我们不管样式
- 微信块是我们注入的：一个悬浮按钮 + 点击展开的二维码图片，纯 CSS/JS，约 30 行

## 四、安全与风险

| 点 | 说明 | 处置 |
|---|---|---|
| 粘贴任意 `<script>` 会原样在访客浏览器执行 | 这是给站主自己用的口子 | 只有站主本人能编辑自己的站，风险可控。输入框旁标注"仅粘贴你信任的第三方客服/统计代码"（符合"错误处理只在系统边界做"） |
| 第三方客服依赖外部 SaaS | Tawk.to 若关停，聊天窗消失 | **网站主体不受影响**，只少一个浮窗，不白屏。选第三方时已接受此取舍 |
| 微信二维码 | 纯静态图片 | 无外部依赖，完全符合信念 4 |
