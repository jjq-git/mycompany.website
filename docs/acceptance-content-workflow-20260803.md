## 三、已通过的业务能力

### 3.1 内容模板/详情模板

- 首次明确写操作会持久化默认详情模板。
- 可创建和复制详情模板，复制件使用独立 ID 且不会继承默认状态。
- 默认模板唯一；默认模板禁止删除，先切换默认后可删除旧模板。
- 模板名称、组件顺序和 SEO 规则可由后端保存。
- 可重复组件按显式 `order` 稳定排序；单一数据源组件按现有规则去重。
- 所有公开详情组件均存在构建渲染器；隐藏组件、空值降级、媒体、规格、表格、链接、图文列、文件、FAQ、关联内容和自由正文的解析/渲染回归通过。

### 3.2 新建内容

- 向导必须选择有效分类和有效详情模板；非法分类/模板返回 400。
- 进入编辑器时 `item_id=0`，保存前不写数据集，取消不会留下空记录。
- 当前实现会校验 Slug、标题、简介和所选媒体；重复 Slug、危险 Slug 会被服务端拒绝。
- 合法内容保存后生成正式 ID，标签按逗号等分隔符结构化，普通内容不会创建单条 `modules` 覆盖。
- 复制先进入临时副本编辑态，自动生成唯一 `-copy` Slug；保存后才形成新记录。

### 3.3 修改、删除、多语言和权限

- 合法标题、摘要和标签修改后可保存并在内容列表搜索回显。
- 现代内容中心删除接口能区分不存在记录（404）和存在记录（200 + `ok=true`）。
- 缺失语言版本可回退源语言打开；首次保存会建立语言副本，不覆盖默认语言数据。
- 团队 viewer 可查看内容，但所有内容写请求返回 403。
- 修改后的详情页在 `zh-CN` 和 `en` 输出中均生成；标题、摘要、标签、SEO 与 canonical 正常，构建报告无失败。

## 四、部署前 P1 整改项

### CONTENT-P1-01 现有内容可以清空核心必填字段

位置：`app/core/routes.py:7654-7690`、`app/core/routes.py:7747-7763`。

必填校验被放在 `if is_new_content` 内，修改已有内容时只对“非空 Slug”执行格式和重复检查。直接 POST 空 `slug`、空 `title`、空 `summary`、空 `cover` 会返回成功并覆盖原数据。浏览器 `required` 不是安全边界，脚本请求、旧客户端或前端异常都能绕过。

风险：详情 URL 丢失、列表与 SEO 标题为空、构建结果退化；属于内容完整性问题。

修复要求：

1. 新建和修改共用同一套服务端字段校验函数。
2. 至少始终校验 `slug`、`title`；其余字段按选中模板的字段契约校验。
3. 校验失败返回 400，不写 YAML、不更新时间、不写成功审计。
4. 增加绕过前端的 POST 回归用例。

### CONTENT-P1-02 修改内容时可保存不存在的详情模板 ID

位置：`app/core/routes.py:7501-7533`、`app/core/routes.py:7838-7865`。

有效模板 ID 只在新建内容阶段校验。已有内容提交 `template_id=dangling-template` 会成功落盘；后续编辑和构建再静默回退默认模板，数据与界面显示关系不一致。

修复要求：所有保存都必须确认模板属于当前站点、当前数据集和当前语言可用模板集合。失效 ID 返回 400；若模板刚被其他请求删除，应提示刷新并重新选择，不得静默写入悬挂引用。

### CONTENT-P1-03 详情模板保存接口接受组件白名单之外的类型

位置：`app/core/routes.py:7400-7419`。

`save_modules` 直接调用通用 `_parse_modules_form`，没有把 `module_N_type` 限制在 `_get_detail_template_components()` 的详情组件集合。隔离测试提交 `hero_banner` 后成功写入详情模板。

风险：可绕过 UI 生成模板管理页无法解释的配置；通用模块字段可能读取错误上下文，形成不可维护或异常详情页。

修复要求：服务端建立详情模板允许类型集合，同时校验 variant、字段类型和 `allow_multiple`；未知类型或非法字段整体拒绝并返回 400，不得部分保存。

### CONTENT-P1-04 模板字段契约没有驱动编辑器和服务端校验

位置：`app/core/routes.py:684-715`、`app/core/routes.py:911-1030`、`app/core/routes.py:7654-7690`、`app/templates/dashboard/panel_detail_templates.html:167-179`。

默认模板声明 `required_fields: [title, slug]`，但新建接口额外硬编码简介和媒体必填；`_detail_template_field_requirements()` 又把简介、媒体、分类、标签固定为显示。模板管理 UI 没有编辑 `required_fields`/`optional_fields` 的能力，SEO 也只有隐藏字段。

风险：模板声明、录入页面和后端规则三套真相不一致；空值隐藏、不同内容类型的字段需求和错误提示无法可靠按模板变化。

修复要求：

1. 明确唯一字段 schema，包含字段名、显示、必填、类型、默认值、空值行为和媒体能力。
2. 模板编辑器可配置允许开放给用户的字段规则和 SEO 规则。
3. 新建与修改的 UI、服务端校验、构建降级都读取同一 schema。
4. 切换模板时重新计算字段，明确保留但隐藏的旧数据，不静默删除。

### CONTENT-P1-05 旧新建入口绕过统一内容向导

位置：`app/core/routes.py:7474-7487`、`app/templates/dashboard/panel_data_list.html:2117,2528,2587`。

`POST /_dataset/<dataset>/new` 仍被旧界面调用，会立即写入仅含“新条目 N”、`item-N` 和默认模板 ID 的占位记录，没有简介和媒体，也没有选择分类/模板、临时编辑态或统一必填校验。

风险：同一个“新建内容”动作产生两种数据质量和取消语义，留下不完整记录。

修复要求：移除旧 UI 调用或让旧路由统一跳转/委托新的临时新建流程；全仓只保留一个创建业务服务。迁移前扫描并处理已有“新条目 N / item-N”占位数据。

### CONTENT-P1-06 详情模板缺少文档要求的预览功能

位置：`docs/详情模板.md:554,759,946`、`app/templates/dashboard/panel_detail_templates.html`。

产品文档要求选择示例/当前数据预览模板，并验证字段缺失、空值隐藏、组件降级和桌面/移动效果；当前模板管理页没有“预览模板”按钮或对应入口。Playwright 已确认页面不存在该操作。

修复要求：提供不修改内容数据的模板预览；可选择一条当前数据或安全示例数据，支持桌面/移动尺寸，展示空值/缺字段状态；预览与正式 builder 必须共用渲染路径。

### CONTENT-P1-07 YAML 数据集并发写会丢更新并可能重复 ID

位置：`app/core/datasets.py:1-61`。

`add/update/remove` 均为无锁的“读全表 → 修改 → 原子覆盖”。并发隔离测试中两个 `add` 都返回 ID 1，最终只保留后写入的一条。源码注释已将其作为低频单店主取舍记录，但浏览器重复提交、多标签页、编辑者协作和自动任务都能触发。

修复要求：部署前至少对同一 `site_id + dataset + lang` 串行化写入，并引入乐观版本/ETag 防止旧页面覆盖新版本；规模化时迁入具备事务和唯一约束的数据存储。并发创建、并发修改、删除与修改竞态必须有自动化测试。

## 五、P2 整改项

### CONTENT-P2-01 内容 Slug 的 HTML `pattern` 在 Chromium 中无效

位置：`app/templates/dashboard/panel_data_list.html:382,2369`。

`pattern="[a-z0-9][a-z0-9-]{1,28}[a-z0-9]"` 在 Chromium 的 `v` 正则语义下字符类非法。浏览器控制台会报 `Invalid character class`，读取 `patternMismatch` 和表单 `checkValidity()` 均会报错并忽略该 pattern。服务端仍能拒绝非法 Slug，但前端反馈失真。

修复要求：转义字符类中的连字符，例如与已修复建站表单采用同一兼容表达式；增加 Chrome/Firefox/Safari 的合法、大小写、首尾连字符、长度边界用例。

### CONTENT-P2-02 旧删除入口对不存在记录也提示成功

位置：`app/core/routes.py:7955-7964`。

`datasets.remove()` 没有返回删除数量，旧路由不检查目标是否存在；删除不存在 ID 仍 302 并 flash“已删除”。现代内容中心接口已经正确返回 404。

修复要求：旧调用统一迁移到现代接口，或让存储层返回是否删除并在路由中返回 404；成功审计只能在真实删除后产生。
