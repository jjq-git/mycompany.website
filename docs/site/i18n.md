# 多语言 + AI 翻译（Phase 2）

## 一、语言数受权限

用户能开几种语言由权限决定（非无限）。划分方式（套餐 / 配额字段）暂不定；启用语言前校验「已启用数 < 上限」，超了提示升级。

## 二、主线

- 源语言 = 用户建站时选的、用来填内容的语言（无平台固定默认语言）。建站时拷主题 `i18n/<源语言>/` 整套作初始内容（见 [sites.md](sites.md)、[meta.yaml.md](../themes/meta.yaml.md)）。
- 逐条 AI 翻译到目标语言，译文存 `sites/<id>/lang/<目标语言>/`，不覆盖源语言、缺字段回退源语言。
- 每语言出独立静态目录（`/en/`、`/ja/`），按访客语言跳转 + 切换器。

## 三、三层翻译策略

方向永远是源语言 → 目标语言。

| 层 | 是什么 | 用在 |
| --- | --- | --- |
| 1 词汇表 glossary | 不翻 / 强制译法 | 品牌词、固定术语 |
| 2 人工覆盖 override | 人工写好，优先级最高 | 首页 / 关于等门面页 |
| 3 AI 翻译 | 兜底，走 hash 缓存 | 产品 / 案例等长尾 |

## 四、hash 缓存（解决同步）

每段源文算 hash 当 key 存译文：源文没变不重翻（省钱），改了只该条失配、重翻（同步），老译留作参考。

```text
"智能门锁 Pro"   → a3f2 → translations[en][a3f2] = "Smart Lock Pro"
改成 "Pro 2 代"  → b7e1 → 查无 → 标「待翻译」（老译留参考）
```

## 五、HTML 保护

富文本不整段送 AI：BeautifulSoup 抠出文本节点翻、再注回，保住标签结构。

```text
<p>我们的<strong>智能门锁</strong></p>
→ ["我们的","智能门锁"] → 翻 → <p>Our <strong>smart lock</strong></p>
```

## 六、词汇表 glossary.yaml

每站一份，AI 预填、用户审核：

```yaml
do_not_translate: [智能门锁 Pro, 我的公司, LOGO]
force_translate:
  zh_to_en: { "联系我们": "Contact Us", "了解更多": "Learn More" }
```

## 七、操作流程（逐条点击）

1. 源语言填完内容 → 设置启用一门目标语言
2. 翻译界面：源 / 目标并排逐条列出
3. 逐条点「翻译」：套 glossary → 抠 HTML 文本节点 → hash 查缓存（变过 / 没翻才调 AI）→ 填入
   （另有「翻译全部未翻译」一键，附 cost 预估）
4. 逐条校对可改；改的记入 override，下次不再 AI 翻
5. 发布

## 八、技术细节

- 模型 gpt-4o-mini 或国产同级；支持自带 API key
- 缓存键：站点 + 语言 + hash
- 数据集分批翻，避免单任务超长
- Prompt 注入「已译术语清单」保风格一致

## 九、发布

每语言独立目录（`/en/`、`/zh/`），sitemap 含所有语言 URL + `hreflang`；字体子集化按语言分做（见 [publish.md](publish.md)）。

## 十、不做

| 不做 | 为什么 |
| --- | --- |
| 自动检测访客语言显示 | 302 重定向 + 切换器即可 |
| 翻译记忆库 TM | 小企业用不上 |
| 术语表管理 UI | 一份 YAML 够 |
| 实时翻译（访问时翻） | 违背静态站 |
| 强制翻所有语言 | 用户自选 |
