# 模块排版变体视觉设计

使用这个 skill 为模块创建新排版变体，或优化已有模块变体的视觉效果。

当前项目里“变体机制已经存在”。创建新变体时要依靠这个 skill 定方向、定结构、定缩略图和验收标准，但通常不要重做系统架构。重点是：

- 为新变体判断是否值得新增、适合什么场景、应该长什么样；
- 让后台缩略预览更清晰、更好看、更能表达真实布局；
- 让前台模块变体的视觉效果更专业；
- 让同一模块的多个变体形成一套统一的设计语言；
- 让新建变体能顺着现有数据结构和保存逻辑接入。

当前项目技术栈：

- Flask/Jinja 模板
- `app/static/js/admin_modules.js` 中的原生 JavaScript
- Bootstrap 5 + `app/static/css/admin.css` 自定义样式
- 站点/页面 YAML 数据：`sites/<site_id>/lang/<lang>/pages/*.yaml`
- 后台模块编辑 UI：dashboard 面板模板

## 设计目标

好的模块变体应该同时满足：

1. **一眼看懂**：后台缩略图能快速看出列数、图文方向、主次层级。
2. **真实可信**：缩略图表达的结构必须接近前台实际渲染，不做“骗点击”的假预览。
3. **视觉克制**：少用花哨装饰，优先通过留白、对齐、比例、层级、节奏提升质感。
4. **变体有差异**：不同变体之间不仅换个方向，还要有明确使用场景。
5. **风格统一**：同一模块系列的圆角、间距、标题层级、图片比例和按钮风格要一致。
6. **移动端可用**：桌面好看之外，手机端不能挤、乱、遮挡或产生横向滚动。

## 先判断问题

创建或优化变体前，先判断需求属于哪一种：

- **新增变体**：现有变体不能覆盖用户想要的使用场景，需要一个新的布局选择。
- **优化变体**：已有 variant id 和功能可用，但缩略图、前台比例、间距或响应式效果不好。
- **合并/删减变体**：多个变体差异太小，导致用户选择困难。

优化已有变体时，继续判断它“难看”在哪里：

- 缩略图问题：太抽象、太空、比例怪、层级不清、和前台不一致。
- 前台布局问题：间距乱、图片比例不稳、文字过长溢出、卡片高度参差、主次不明显。
- 变体策略问题：多个变体差异太小，或者没有覆盖常见使用场景。
- 响应式问题：桌面可用但移动端挤压、堆叠顺序不合理。
- 数据适配问题：只有理想数据好看，标题长、图片缺失、项目数量变化时崩。

先修结构和比例，再修颜色和细节。

## 常用变体方向

为模块创建新变体时，优先从真实使用场景出发：

- **网格类**：`grid_2`、`grid_3`、`grid_4`、`grid_6`
  - 适合功能、产品、图标卡片、合作伙伴。
  - 重点控制卡片宽高、标题行数、图标/图片尺寸、间距。

- **图文类**：`image_left`、`image_right`、`image_top`、`image_background`
  - 适合介绍、亮点、案例、产品卖点。
  - 重点控制图片比例、文字最大宽度、按钮与标题间距。

- **强调类**：`featured_card`、`split_feature`、`centered_statement`
  - 适合首页重点模块或品牌信息。
  - 重点做强主标题、弱化说明，避免整块像普通卡片列表。

- **列表类**：`list_vertical`、`list_horizontal`、`timeline`、`numbered_steps`
  - 适合步骤、规格、服务流程、优势说明。
  - 重点控制序号/图标、连接线、行距和扫描效率。

- **媒体类**：`carousel`、`masonry_like`、`gallery_grid`
  - 适合图片多、案例多、产品细节多的模块。
  - 重点控制裁切、比例、空图状态和移动端滑动体验。

新增变体前先问：它是否解决了已有变体没有覆盖的内容场景？如果只是微小差异，优先优化已有变体。宁可 4 个好变体，也不要 12 个差不多的变体。

## 新建变体决策

当用户要求“新增一个变体”时，按这个顺序做判断：

1. **确认内容类型**：这个模块主要展示图片、文本、卡片、数据、步骤、媒体，还是混合内容？
2. **确认展示目标**：是强调品牌、提高扫描效率、展示更多项目、突出单个重点，还是适配移动端？
3. **确认和已有变体的差异**：新变体必须在结构上明显不同，例如列数、图文关系、主次层级、列表节奏或媒体展示方式不同。
4. **确定默认数据适配**：用 1/2/3/6 项数据都要能成立；缺图、长标题不能破版。
5. **确定缩略图语言**：先画出后台缩略图结构，再让前台布局与它对应。

新变体必须同时交付：

- variant id；
- 后台选择器标签；
- 后台缩略预览；
- 前台实际布局；
- 响应式规则；
- 旧数据 fallback。

## 缩略预览标准

后台缩略图要像“小型线框稿”，不是截图。

必须做到：

- 用 HTML/CSS 结构画布局，不用上传图片或静态截图。
- 缩略图内的图片区域、标题线、正文线、按钮/图标位置要和真实布局一致。
- 每个变体的视觉重心清楚：图在哪里、文字在哪里、几列、是否轮播。
- 同一组缩略图的边距、线条粗细、圆角和灰度风格统一。
- 缩略图不要过度装饰；颜色只用于表达选中态、图片区或重点区域。

推荐 class 风格：

```css
.mini-grid-3 { ... }
.mini-image-left { ... }
.mini-steps-numbered { ... }
```

缩略图只表达结构，不承载真实内容。

## 前台视觉标准

优化前台变体时优先检查：

- **外层节奏**：模块上下间距是否和页面其他区块一致。
- **内容宽度**：文本行宽不要过长，图片不要小得尴尬。
- **对齐关系**：标题、说明、按钮、图片边缘是否有明确对齐线。
- **图片比例**：使用固定 `aspect-ratio` 或明确高度，避免加载后跳动。
- **文字防溢出**：长标题、长描述、多语言文本要有合理换行和最大宽度。
- **卡片一致性**：同一行卡片高度、内边距、图片区比例尽量统一。
- **空数据状态**：无图、少于预期条目、多于预期条目都要能看。
- **移动端堆叠**：图文左右在手机端通常改为图上文下；重要内容优先。

## 开始前先读

改代码前，先查看目标模块当前实现：

- 模块编辑器和变体切换：
  - `app/templates/dashboard/panel_page_edit.html`
  - `app/static/js/admin_modules.js`
  - `app/templates/dashboard/_block_palette.html`
- 后台缩略预览/变体样式：
  - `app/static/css/admin.css`
- 现有模块模板和数据结构：
  - 在 `app/templates` 和 `sites/*/lang/*/pages/*.yaml` 下搜索
  - 如果目标模块有 metadata、schema 或独立模板，先读对应文件

优先用 `rg` 搜索目标模块类型、已有 variant id、预览 class 名。

## 工作流程

1. 确认目标模块和已有变体。
   - 找到已有 variant id、缩略图结构、前台渲染模板和 CSS。
   - 判断是只优化视觉，还是需要新增变体。

2. 先定设计方向。
   - 给每个变体一句用途说明，例如“适合 3 个核心卖点”“适合图文介绍”“适合步骤流程”。
   - 删除或合并差异太小、用途不清的方案，除非用户明确要求保留。

3. 新建变体时先补完整链路。
   - 添加稳定的 variant id。
   - 添加后台选择器选项。
   - 添加对应缩略图结构。
   - 添加前台布局 class 或渲染分支。
   - 保持旧 variant id 不变。

4. 优化后台缩略图。
   - 让缩略图更像真实布局。
   - 统一圆角、线条、间距、灰度和选中态。
   - 确保缩略图在小尺寸下仍然清楚。

5. 优化前台布局。
   - 优先用 variant class 控制布局。
   - 避免为每个变体复制大段模板。
   - 用 `aspect-ratio`、`minmax()`、`clamp()`、`max-width` 等稳定布局。

6. 接通或保留保存逻辑。
   - 新增变体时确保 variant id 会保存。
   - 优化已有变体时不要改变已保存的 id，除非同时做兼容迁移。

7. 做响应式和边界数据检查。
   - 检查 1 项、2 项、3 项、多项数据。
   - 检查长标题、长描述、缺图。
   - 检查桌面和手机端。

## 实现模式

能用这个结构时，优先保持隐藏字段：

```html
<input type="hidden" name="module_{{ i }}_variant" value="{{ module.variant or 'default' }}">
```

大多数 markup 相同时，用 variant class 控制布局：

```html
<section class="builder-module feature-grid feature-grid--{{ variant|default('grid_3') }}">
  ...
</section>
```

后台缩略预览 CSS 和前台布局 CSS 要分开：

```css
.variant-preview .mini-grid-3 { ... }      /* 后台缩略图 */
.feature-grid--grid_3 { ... }              /* 前台布局 */
```

## 禁止事项

- 不要引入 Vue、React、Tailwind、Element Plus 或 BootstrapVue。
- 不要把现有后台构建器改成新框架。
- 不要为了“高级感”添加大面积渐变、发光、装饰圆球或复杂动效。
- 不要用上传图、截图或静态图片做布局缩略图。
- 不要只改后台缩略图却不检查前台实际效果。
- 不要破坏现有 YAML 数据结构；缺失值要迁移或给默认值。
- 不要把某个站点的具体内容硬编码进通用模块变体。
