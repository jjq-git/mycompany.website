当用户说"review 一下"、"代码审查"、"检查这段代码"、"看看有没有问题"时触发.
对照 CLAUDE.md 定义的 7 条核心信念和"不做的事"清单,审查代码变更.

这不仅是找 bug,而是确保新功能没有偏离产品定位——
"任何决策犹豫时,问自己一句:如果我自己用这个产品,这样做合理吗?"

## 审查清单(对照 CLAUDE.md)

逐条对照以下清单:

**一、核心信念符合度**

| # | 信念 | 检查点 |
|---|------|--------|
| 1 | 输出永远是静态 HTML | 新增功能是否依赖后端运行时?如果是,违规 |
| 2 | 用户应填表,不该写代码 | 是否让用户碰了 HTML/CSS/JS? |
| 3 | 模板要少而精 | 是否新增了不必要的模板?模板是否够精致? |
| 4 | 平台死了,网站不能死 | 新增功能是否依赖平台持续运行?ZIP 导出还能用吗? |
| 5 | 速度是产品的一部分 | 是否引入了大文件/慢请求?首屏是否 < 1 秒? |
| 6 | 简单 > 优化 | 是否有过度优化的代码?为了省几十 MB 增加了判断逻辑? |
| 7 | 低频用户友好 | 6 个月没登录的用户回来还能用吗? |

**二、"不做的事"符合度**

- [ ] 是否引入了可视化模板编辑器?
- [ ] 是否让用户改 CSS/HTML/JS?
- [ ] 是否新增了第 4+ 套粗糙模板?
- [ ] 是否在 Phase 1 做了多语言?
- [ ] 是否添加了按月订阅?
- [ ] 是否添加了密码登录?
- [ ] 是否引入了整页所见即所得编辑器?
- [ ] 是否添加了评论/论坛/用户系统?
- [ ] 是否添加了在线交易/购物车?

## 代码质量检查

**CLAUDE.md 第七节 代码风格**:

- [ ] 代码是否简洁?(能 30 行写完的不写 100 行)
- [ ] 是否过度抽象?(MVP 是否为了"未来可能的需求"留了接口)
- [ ] 注释是否用中文?代码(变量名、函数名)是否用英文?
- [ ] 注释是否说明了"为什么"而不只是"做了什么"?
- [ ] 错误处理是否只在系统边界(用户输入、外部 API)?
- [ ] 内部代码是否相信调用方?
- [ ] 是否引入了不必要的新依赖?

## 安全检查

- [ ] 用户输入是否做了基本验证(XSS、注入)?
- [ ] 文件上传是否限制了类型和大小?
- [ ] 敏感数据(密钥、密码)是否不在代码中硬编码?
- [ ] `.env` 是否在 `.gitignore` 中?
- [ ] SQL 查询是否用了参数化(SQLAlchemy ORM 默认为参数化)?
- [ ] 是否有路径遍历风险(`send_from_directory` 验证)?

## 数据兼容性检查

- [ ] 是否修改了 `models.py` 中已上线的表结构?(只增不减)
- [ ] 新增字段是否有默认值?
- [ ] 站点文件夹结构是否向后兼容?
- [ ] YAML 数据格式变更是否兼容旧数据?

## 审查报告格式

审查结论采用以下格式:

**通过项**:列出符合上述所有检查点的部分

**问题项**(按严重程度):
- 🔴 阻断:违反核心信念或"不做的事",必须修改
- 🟡 建议:可以改进但非阻断
- 🟢 赞赏:做得好的地方

**具体问题**:
```
1. 🔴 <问题标题>
   文件:<file>:<line>
   问题:<描述>
   违反:<哪条信念/规则>
   建议:<怎么改>
   是否影响 ZIP 导出:是/否
```

## 常见违规示例

| 违规 | 典型代码/设计 | 为什么不行 |
|------|--------------|-----------|
| 引入运行时依赖 | 加了 WebSocket 实时推送 | 静态网站不需要后端 |
| 让用户写代码 | 后台加了个 CSS 编辑器 | 模板升级会冲突 |
| 过度抽象 | 为了 2 种数据集抽象了 DataSourceFactory | MVP 阶段不需要 |
| 增加不必要的依赖 | `pip install redis` | 依赖能少则少 |
| 过度优化 | 对 20 个产品做了 LRU 缓存 | 简单 > 优化 |
| 做了多语言 | Phase 1 加了 i18n | Phase 2 才做 |
